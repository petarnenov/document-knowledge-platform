## SDLC and reporting

Follow requirements and architecture analysis → OpenSpec/contract/design/test plan → independent specification review and recorded automatic approval → implementation with tests → local verification in the pinned Linux CI environment and source-bound coverage/security/contract/E2E evidence → independent implementation review and fixes with revalidation → push/PR → CI confirmation of the published commit → reviewed integration into dev after all applicable gates → completion audit/archive. Preserve scope and evidence at every transition.

Before starting each task in this queue, search open and closed issues and reuse a suitable prioritized issue; create one only after the mandatory duplicate check. An existing suitable issue satisfies issue-before-work. Record acceptance and verification criteria, then link the issue in the task checklist and PR. Track independently executable/delegated items separately beneath a package issue. Close issues only after their verified completion/integration evidence is recorded. This covers specifications, code, tests, fixes, reviews and protocol/delivery work; preexisting work is backfilled explicitly. See the mandatory issue lifecycle in `docs/development/worktree-workflow.md`.

After every verified task closure, save the resumable handoff and run `/compact` in the current session where supported before the next task. Preserve the full goal and unresolved work; record a pending compaction checkpoint honestly when the environment provides no invocation mechanism.

While work is active, publish a structured status at least every 15 minutes with completed, in-progress and blocked tasks, executed verification/results and next actions. Brief findings between these reports do not replace the periodic task/execution status. Resume the full queue after interruptions; package completion is a milestone, not the end of the project goal.
