## Port, execution and bounded work

Keep `emit()` synchronous and bounded: validate/encode/admit in memory only, with no filesystem/network work, promises to await, registration or implicit flush. Add an optional Node-only spool port as a fourth producer constructor argument; existing three-argument behavior remains supported. A spool is explicitly opened asynchronously by the bootstrap before constructing a producer. Its subsequent initial `load` returns an already-loaded bounded snapshot without I/O; all replacement/close operations belong to the single asynchronous dispatcher/lifecycle owner. Do not start a competing writer or resolve `whenClosed()` before the actual current request/filesystem operation exits.

Bind each spool to the exact original buildId/runId/instanceId/component/gitSha/sourceFingerprint and producer credential fingerprint, using a fixed key order and reviewed credential-digest namespace. Never store bearer/registrar/reader/session/CSRF material. No changed build, credential or execution may adopt old events. Bound2048 events/8MiB of canonical event data,8192 UTF-8 bytes per event,9MiB snapshot and64MiB retained/staging disk allowance. Snapshots contain only binding metadata and original canonical sanitized event strings; every restored event is validated through the same current wire/vocabulary and must reproduce its exact original canonical bytes/identity/event ID. Reject malformed, oversized, duplicate, unknown-field or changed-binding snapshots; never replace them with an empty queue. Treat restored pending events as UNKNOWN until exact scoped receipts prove otherwise, even if their previous submission state was not persisted.

The dispatcher persists its current pending snapshot before submitting a batch, reconciles restored/UNKNOWN original IDs through fixed receipts and uses unchanged IDs for any idempotent resend. Persist removal of committed/rejected/expired entries during the normal dispatcher lifecycle; no `close()` flush guarantee. A close racing an operation waits only through the separately observable worker lifecycle; `close()` itself returns immediately. A retained old committed snapshot is safe to reconcile again, and must never be described as disk-empty merely because in-memory pending is0. Port failure is visible as degraded/unspooled state and preserves prior evidence; no recursive logging or hidden loss. ## Replaceable filesystem adapter

Use Node built-in asynchronous filesystem APIs only, in a separate Node-only module and export with TypeScript declarations. Require a canonical absolute private directory owned by the process UID, mode0700, and bounded regular mode0600 files with no symlinks; verify ownership/type/size and before/open-file identity around reads. Atomically replace a bounded staged snapshot after file sync, then sync the directory. Preserve the last known snapshot and expose errors on failed storage operations. No raw error text or private path is an emitted log event.

Claim an exclusive mode0600 `queue.lock` with exclusive creation before loading/writing. Record a random lease identifier and process ID as bounded private operator metadata, not a credential. A second opener or any preexisting lock fails closed with a fixed lock/busy diagnostic; never unlink or automatically steal a lock based on PID age or guessed process death. Normal graceful producer shutdown closes the owned port after dispatcher quiescence, verifies the exact owned lock file identity/lease bytes and removes only that lock. An interrupted process preserves the queue and lock for explicit operator recovery after exact owner-death proof; automatic stale-lock reclamation and pathological filesystem cleanup remain outside this normal increment and must not be reported as verified. This scope does not claim unattended crash-lock recovery. A supervisor may later provide another exclusive spool adapter through the same port without modifying event/domain behavior.
