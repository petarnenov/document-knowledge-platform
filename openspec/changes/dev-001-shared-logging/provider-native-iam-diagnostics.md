## Narrow implementation boundary

Add a runtime-owned `BootstrapFailure(ValueError)` to `rustfs-runtime.py`. It carries only a closed source-defined failure category plus optional closed method (`GET`, `PUT`, `HEAD`, `DELETE`), authority (`root`, `app`, `cleanup`, `anonymous`), operation kind and bounded numeric HTTP status or process exit code. Operation kinds are fixed labels for bucket/versioning/policy, IAM policy/user/binding, synthetic object/version, version-list and admin-info requests; unknown inputs yield a fixed UNKNOWN label. Dynamic URL/query/key/credential values never become labels. Categories cover original transport process/deadline failures, rejected or malformed HTTP result, header/response bounds, fixture version/readback/privacy/listing/delete/absence invariants, and bucket ownership/privacy/versioning checks. The exact category set is AUTHORITY_COMMAND, TRANSPORT_PROCESS, TRANSPORT_DEADLINE, REQUEST_HTTP, REQUEST_STATUS_INVALID, RESPONSE_BOUND, HEADERS_BOUND, BUCKET_OWNERSHIP, BUCKET_POLICY, BUCKET_VERSIONING, APP_VERSIONING, FIXTURE_VERSION, FIXTURE_READBACK, PRIVACY_DENIAL, FIXTURE_LISTING, FIXTURE_UNCHANGED and FIXTURE_ABSENCE. The exact operation-kind set is BUCKET, BUCKET_POLICY, BUCKET_VERSIONING, IAM_POLICY, IAM_USER, IAM_BINDING, OBJECT, OBJECT_VERSION, VERSION_LIST, ADMIN_INFO and UNKNOWN. HTTP status is an integer100–599; process exit code is an integer−255–255, never boolean. Missing numeric context stays absent, not an invented status. Unknown method/authority supplied to diagnostic construction is rejected; unknown request paths map only to operation UNKNOWN. Reject unknown category/context fields; validate optional fields before constructing the public category. Render a bounded ASCII category from these closed tokens and validated numbers only (at most256 characters). A malicious exception message, URL, body, header, configuration, command or environment must never enter the category or exception text.

The existing `upload-runtime.stage('native-iam', ...)` already propagates a runtime exception's category into its fixed safe stage summary. Use that path to retain the closed IAM diagnostic; do not print raw causes, arguments, credential identifiers, signed requests, response bodies, SQL, private paths or uploaded content. Preserve the original exception's ValueError compatibility and safe default CLI output. No network client, global logging service locator, business behavior, credential authority or new public API belongs in this support.

Annotate the original actual failure sites and requests without changing their execution order, expected status sets, XML/privacy assertions, signatures, TLS checks, ownership, resource bounds, process/deadline values, cleanup or exception suppression policy. Process errors may expose only a validated bounded numeric exit code, never stderr. HTTP errors may expose a validated three-digit status, never response text. Semantic failures use explicit source-owned categories; do not infer a cause from arbitrary exception messages or privately introspect SDK state. Optional request context is diagnostic only and must not authorize or alter the request. No retries, sleeps, readiness promotion, partial-state adoption or cleanup sweep is introduced. Retain failed/unknown outcomes as failed/unknown.

This change improves the existing original operator startup diagnostic. It does not by itself adopt this interpreted helper into shared API logging or close the rank4 producer inventory; original compiled provider main/phase adoption, remaining infra/buildCI producers and combined acceptance remain separate required gates.
