## Small adapter composition

Keep BrowserLogGateway as the application-facing port. Implement replaceable durable pending storage and a gateway decorator in adapters-out; keep credentials and filesystem code out of application/kernel and never depend on another service or adapters-in. Bootstrap composes the existing HTTPS gateway, durable adapter and a single replay coordinator. The coordinator submits at most one replay through the existing BrowserLogRequests two-worker/sixteen-queued/eighteen-charged dispatcher with a fresh five-second replay-operation deadline. It must not forward on the deadline scheduler or use the business/offload executor. Route admission retains its original five-second budget; timeout does not release a running worker/claim. No new public route or ingestion/store is introduced.

The coordinator may wait for its one result on one private lifecycle-owned thread. It cannot submit another replay until the previous replay actually exits, including after a decided timeout. Retry transient failure with bounded 1..30-second backoff; no busy-loop or unbounded drain. Shutdown stops admission/coordinator, retires queued replay and keeps ownership until actual work exits before closing the store/HTTPS client. Record truthful incomplete shutdown; do not release the lifetime store lock while an owned writer can still touch files.

## Durable acceptance and original authority

Only the existing session/Origin/CSRF/context checks and closed canonical BrowserLogJson.batch validation may supply a batch. Copy trusted immutable scope under the session transition lock; release it before disk/network work. The decorator durably records the sanitized canonical batch before forwarding. Never persist the browser envelope, CSRF, cookie, session/access/refresh token, arbitrary console/error text or document content.

Persist the original delegated logging credential and immutable scope/binding privately, separate from sanitized pending payload. It is a logging scope token, never a browser/domain token. Include original parent/scope/epoch, artifact digest/build/run, verified issuer/subject/tenant, finite capture/replay expiry and endpoint/CA binding; bounded strictly parsed records and redacted string representations only. An adapter-owned checkpoint/recovery SPI hides these values from the application-facing opaque Scope. Recovery validates the exact configured endpoint/CA/bridge parent and installed original portal manifest before restoring that original scoped handle. Do not delegate a replacement scope, renew a grant, relabel a build/run or assign a pending record to a new session/tenant.

Normal process restart reopens the same owned browser spool and unchanged finite bridge-parent binding. The process lifecycle producer may use a new run/instance independently. Retain configured original portal bindings while their accepted queues remain replayable. A changed bridge parent/configuration requires a controlled drained/expired-spool transition; reject mismatch and retain evidence instead of silently adopting/rebinding old work. General automatic migration is outside this normal increment.

A new browser request after retirement remains rejected. Already accepted server records may replay under their original scope until its original replayUntil; this never restores browser or business authority. Claims prevent the foreground and replayer forwarding/removing the same stored record concurrently. Repeated identical scope/batch admission reuses the pending record; conflicting/corrupt records fail closed. Retain original event IDs and bytes. Upstream idempotency handles an unknown commit/restart; no response timeout implies rollback or historical absence.

Delete a pending record only after validating an exact all-COMMITTED response for its event IDs, or after a terminal local discard. Validate upstream receipt shape/IDs before deletion inside the outbound composition, without importing adapters-in. Auth revocation/expiry, invalid/conflicting/expired-event responses are terminal for that exact record; record local discard with delivery uncertainty rather than retrying under fresh credentials. Transient transport/429/503 failures retain it. A confirmed upstream commit followed by local checkpoint failure remains pending/degraded and may replay idempotently.

## Private ownership and bounds

Require an explicit canonical owner-only spool directory in the closed private browser configuration; owned directory0700, regular files0600, no symlinks/foreign ownership. Use one lifetime lock and same-directory atomic, forced stable/staging snapshots. Use one atomic stable/staging snapshot containing separate typed authority-checkpoint and sanitized-payload sections; removal updates their references atomically. Bind payload digest and checkpoint identity. Detect malformed, extra/truncated, mismatched or oversized state before any replay; preserve it for diagnosis. No global cleanup or silent directory recreation/adoption. Updating the configuration shape requires the native operator's exact private-input checks and tests too.

Cap the complete pending queue, including in-flight claims, at2048 charged events and8MiB sanitized bytes. Count overlapping batches conservatively; do not hide charges behind deduplication. Bound each accepted batch to the existing32 events/32768bytes and each private authority checkpoint to8192bytes. Stable/staging snapshots, lock and bounded health metadata together must fit64MiB. Refuse admission explicitly when bounds cannot be satisfied; never evict replayable accepted work to pretend success. Reclaim unreferenced authority only after its last pending record is durably removed. These are functional finite bounds, not final disk/headroom/endurance measurements.

Expose bounded nonrecursive pending/claimed/committed/local-discard/last-degraded counters through adapter status and an owned private health snapshot. Never include credentials or payloads. Browser receipts retain current-scope-only upstream authority and UNKNOWN/EXPIRED/COMMITTED semantics; pending/degraded is never represented as persisted. Beacon204 still requires validated upstream commit; durable-local-only acceptance returns an existing fixed unavailable response and leaves browser delivery unknown. Do not log transport/health/receipt requests recursively.
