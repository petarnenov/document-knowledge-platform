## Typed SDK context and original catalog

Extend `modules:observability-java-sdk` only. Add a small immutable typed diagnostic context/catalog and a separate Throwable capture adapter in `org.documentknowledge.loggingclient`. Keep metadata support JDK-only and dependency direction unchanged; domain/application code must not acquire an SDK, HTTP, filesystem, SQL or framework dependency. Runtime composition and outward instrumentation adapters consume the SDK. No service imports, database access, registration credentials, arbitrary attribute/message maps or tenant/actor authority fields enter this client.

Retain the existing two-argument `LogVocabulary` and seven-argument `LifecycleEvent` constructors as empty-diagnostics overloads. An optional typed diagnostics attachment adds only existing contract fields: status100–599, nonnegative safe-integer remainingDeadlineMs, registered errorCode, five-character SQLSTATE, registered dependency/version/imageDigest/vendorBuildProvenance, exceptionClass, causeClasses, stackFrames, redactedFields/truncatedFields/unregisteredSymbols and optional numeric bytes/queueDepth/boolean cancelRequested attributes. Existing lifecycle count/cleanup fields retain their shape. Omit absent optional fields; no arbitrary strings, Throwable objects, uploaded content, URLs, SQL, headers, exception/console messages or free-form JSON are retained in queued/spooled events.

`LogVocabulary` gains an immutable diagnostic catalog derived ONLY from the original installed manifest: bounded error codes, dependencies, exception classes and frame(symbol, canonical relative source) entries. Preserve existing v1 patterns/cardinalities and exact original dependency values; UNKNOWN provenance remains UNKNOWN. Reject malformed/duplicate catalog entries, unsafe relative sources and ambiguous Java symbol-to-source mappings instead of guessing a file. Old empty catalogs and old lifecycle-only events remain valid. Error/dependency identifiers or version/digest/provenance mismatches reject admission. Unknown exception/frame symbols are omitted and counted, matching collector policy; they are never registered dynamically from failures. Source paths in output come only from this reviewed catalog.

The capture adapter snapshots a real caught Throwable outside the domain and before emission. Never call getMessage/getLocalizedMessage/toString or serialize the Throwable/suppressed graph. Inspect only bounded cause edges (at most4), the root class and at most32 root stack frames; retain only catalog-matching classes/symbols. Resolve a canonical source only from a unique registered symbol and matching actual SourceFile basename; native/no-source frames may retain only a registered symbol. Never copy an incoming stack source path. Preserve nonnegative actual line numbers when present. Missing/unregistered symbols and omitted tail/cycle data have explicit bounded unknown/truncation counters. Raw exception text is withheld without reading it. SQLSTATE is an explicitly typed value supplied by the catching JDBC adapter from the actual exception, never parsed from a message. Capture performs no network/disk/JDBC operation and cannot hold the Throwable in the queued event.

Extend `LogWire.prepare` to validate/sanitize these typed fields BEFORE queue admission. Extend `restore` to rebuild the same typed policy and require semantic equality with the original JSON so extra/unsafe fields or changed execution/catalog cannot be smuggled through durable recovery. Preserve original event IDs/credential binding, lifecycle-only snapshot compatibility,8192-byte event/32768-byte batch/normal queue limits, one asynchronous dispatcher, exact scoped receipts and nonflushing close. `emit` still performs no network/disk I/O or waiting. No queue/transport redesign or exceptional capacity matrix is introduced.

`ApplicationLogRuntime.open` parses the original manifest's full closed diagnostic catalog instead of ignoring it, and exposes a typed operation emission method that reuses its captured original execution, metadata/correlation/trace and producer. Existing startup/shutdown behavior and optional composition remain unchanged; subsequent required service configuration/wiring remains separately verified. Do not mint replacement build identity or accept caller actor/tenant claims. Invalid catalog/config fails with existing fixed bootstrap refusal and owned cleanup.
