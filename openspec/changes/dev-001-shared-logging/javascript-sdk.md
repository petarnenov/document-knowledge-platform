# Normal JavaScript/TypeScript producer SDK — #457

Implement the same reviewed v1 protocol in a small dependency-free ESM SDK with TypeScript declarations, reusable by the existing portal and Node tooling. Keep domain/session authority in the BFF and deployment/operator responsibilities outside the SDK. No new exceptional gates, wire fields, security controls or implicit authority.

- Place framework-free reusable code in sdks/javascript, separate universal typed event validation/encoding/bounded queue, browser delivery and Node delivery entrypoints. Browser imports must not pull Node filesystem/network APIs. Use existing pinned Node/TypeScript/Vitest tooling and no new external runtime dependency. Permit portal composition and Node runtime tools to consume the adapter, with positive/negative import tests.
- Bootstrap supplies original installed build manifest, once-per-page/process runId and instanceId, reviewed catalog and appropriate delivery configuration. No SDK registration, guessed build fingerprint, fabricated buildId, query authority or browser bearer credential. Application build-manifest embedding/adoption and BFF context lifecycle are separately verified wiring work under #457, not claimed by a library-only check.
- Universal typed lifecycle events match the Java wire policy: stable reviewed event/phase, original execution/correlation/time, finite bounded numeric/boolean attributes only. Do not accept arbitrary messages/maps, Throwable/Error text, caller actor/tenant, request/SQL bodies or dynamic symbol catalogs. Sanitize before enqueue; ingress sanitizes again. Event IDs stay unchanged across retry; original capture scope stays attached.
- Bounded emit performs no network/disk work and never awaits delivery. Cap2048 events/8MiB,8192 UTF-8 bytes/event,32events and32768bytes per full envelope including transient browser fields. Duplicate/rejection/overflow/closed state explicit, counters and honest pending/UNKNOWN/COMMITTED/dropped/expired state, no recursive logging.
- Browser adapter uses navigator.sendBeacon only for event submission to fixed same-origin /api/v1/dev-logs/beacon with application/json Blob and current transient CSRF/context fields. true means browser queue acceptance/UNKNOWN persistence only; false retains pending within bounds. Browser has no logger bearer, operator token or authority claim. Session context uses POST /api/v1/dev-logs/context with X-CSRF-TOKEN and original buildId/runId; the response supplies server-owned contextEpoch/expiry and must match the original buildId/runId. Normal authenticated delivery uses the already selected CURRENT_CONTEXT captureClass; unattributed capture remains unavailable without an explicit selected policy. Receipt reconciliation uses POST /api/v1/dev-logs/beacon/receipts with transient body csrfToken, original contextEpoch/buildId/runId/captureClass and at most32 original eventIds. Beacon includes the same contextEpoch/captureClass and original execution in its typed batch. These operations use fixed same-origin paths, credentials:same-origin, no redirects, finite deadline/body bounds and asynchronous reconciliation that never gates business UI. Bootstrap/BFF owns verified epoch and identity transitions; never relabel queued events to a replacement epoch. Retirement removes local delivery authority: old queued events cannot be adopted by a new identity or sent under a replacement epoch. Report local queue discard/retired capture separately from persistence. Previously submitted events retain UNKNOWN persistence unless an exact valid scoped receipt proves COMMITTED; local retirement, elapsed time, Beacon true or inability to reconcile never proves LOG_EVENT_EXPIRED, rollback or confirmed server loss. Never persist CSRF/session tokens or an entire secret-bearing Beacon envelope. Hooks must be removable and close bounded.
- Node adapter receives already-issued producer-only configuration, verified explicit HTTPS CA/authority and existing fixed /batches and /receipts. Use Node built-in HTTPS with no redirects/proxy/ambient credentials, bounded connect/whole5s and32768responsebytes. One dispatcher, finite retry, scoped exact receipts only. Persistent replay, when introduced, uses a replaceable private bounded spool port bound to original execution/credential digest, retaining original IDs and no raw secret. Lifecycle close does not assert a flush/commit; explicit pending/loss state remains visible.
- Verify encoded multibyte/envelope bounds, typed redaction, duplicate/retry IDs, delayed/outage/nonblocking normal operation, sendBeacon true/false and expired-context isolation, valid exact receipts vs UNKNOWN, finite close and browser/Node import separation with >=75% changed lines/branches in pinned Linux. Real browser/BFF/shared PostgreSQL adoption is required subsequently, not replaced by SDK tests. Keep actual shared logger/native producer UP. #458/#459/final measurements remain deferred; full457 requires all producers/two builds/real failed-request cause/PR/CI/dev/post-dev.

Independent exact-revision review and standing development selection must precede JS SDK runtime source edits. SDK library verification alone cannot establish actual application adoption or full #457 completion.
