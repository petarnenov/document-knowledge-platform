## Immutable identities and private port authority

A framework-free ArtifactRegistration binds existing ProducerBinding to exact lowercase manifest/vocabulary digests. Registration input has no caller producer/scope ID. The registry generates new UUIDs and32 random bytes via JDK SecureRandom, encoding a43-character canonical base64url token without padding. The registration call takes an already verified operator authority through its private application boundary; no producer/read token grants that authority. Root creation atomically inserts one parent AND its initial scope and returns their IDs, fixed parent expiry and scope-only token after commit. Existing wire ProducerGrant already includes scopeId. No separate unused parent token is introduced.

The private delegation application input is a verified immutable server grant: at most4096 explicit parent IDs it owns, at most4096 explicit bridge manifest digests, and finite explicit scope permissions (kind plus exact issuer/tenant where applicable; no wildcard tenant). Principal ID and expiry are server configuration, never request claims. The forthcoming authenticated HTTP adapter must derive that grant from its dedicated DelegatorToken before parsing/delegating; this slice alone does not implement that credential adapter. A grant may assert a subject only inside its allowed issuer/tenant scope, based on previously verified operation/session authority. Unauthorized parent/manifest/scope fails403 before mutation. Normal child binding equals parent's exact installed artifact AND run. An explicitly allowed installed bridge manifest may bind the browser's own run under the same parent. Root and delegated scope IDs are generated server-side; delegation returns the SAME parent ID.

A server-owned contextEpoch is supplied only by the verified attestor to the private port (root creation mints its own). Capture ends after at most5minutes. Delegated capture is capped by parent and attestor authority expiry. The operator Registrar authorizes the root create/revoke operation and is revalidated before commit; its credential expiry is not a session/attestor capture horizon. Initial root capture is capped by5minutes and parent expiry. New scope creation rejects nonfuture or later captureUntil. Replay ends at the earlier of parent acceptUntil and scope creation+48h; no replay horizon extension on refresh. The BFF must reject new browser captures after retirement and retain the sealed original scope only for previously accepted server replay; existing scoped authentication is replay authority, not browser context validation or business authority. Those BFF protections remain separate mandatory integration work.
