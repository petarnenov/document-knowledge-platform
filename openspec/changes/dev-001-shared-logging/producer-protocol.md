# Proposed v1 producer, vocabulary and receipt protocol — #457

This is the normative proposed companion to `contracts/v1/dev-logging.yaml`. It requires exact independent review before transport/storage implementation. Slice1 metadata clearance does not approve this protocol.

## Parent registration and scoped delegation

An out-of-band operator installs a reviewed immutable build manifest into the logging boundary's private manifest registry before registering producers. Only the dedicated registration credential can register/revoke parent producers. Its generated secret is neither a producer credential nor a normal reader credential. Registration binds component/build/run/source and installed manifest/vocabulary digests. Reject missing manifests, digest mismatches, unknown components, unknown fields and client-supplied producer IDs. The service generates an opaque parent UUID and a scoped credential; reject collisions rather than reissue an existing UUID. The credential never carries domain/content authority. Source/build claims are diagnostic provenance, not a claim to cryptographically prove browser code authenticity.

A parent is reusable for that exact build/run/component across operation or browser-context events. It lives at most48 hours by server time, cannot be extended or renamed, and cannot be used to rebind an old spool to a new principal. A still-running component may register a fresh parent for subsequent events under its unchanged actual build/run; pending events keep their original parent. Keep at most4096 retained parent registrations globally. Expired/revoked parent state is retained until its replay horizon plus15 minutes, then may be reclaimed independently of seven-day event retention. Unknown/expired/revoked credentials always fail closed. No client-requested parent UUID reuse. Original event records contain immutable scope/provenance snapshots; query needs no live parent join.

An authenticated server attestor can create a delegated scope only under a parent that its configured delegation grant owns. The attestor credential fixes allowed component/build registrations and issuer/tenant authority; no wildcard tenant grant is assumed. Normally a child has the parent's exact artifact/run binding. The BFF is an explicit source bridge: its configured attestor grant may bind a child to an installed served admin-portal manifest and the current browser execution, while retaining the BFF's own parent producer identity. This does not allocate a parent per tab or let it claim another service's compilation. Such bridge grants enumerate permitted components and installed manifest digests. BFF derives actor/tenant from its verified current session; backend adapters derive it from already independently validated operation authority. Browser/event fields cannot supply those claims. Attestor credentials stay on the server and do not grant query permission.

`POST /delegations` returns the SAME parent `producerId`, a new `scopeId` and a server-only scoped token. It does not allocate a new parent. Scope kinds are `TENANT` (verified issuer/subject/tenant), `AUTHENTICATED_UNSELECTED` (verified actor, no tenant), `UNATTRIBUTED` (no actor/tenant) and `OPERATOR_ONLY` (non-user infrastructure). Only explicit operator readers may see the latter three. Tenant readers see only matching TENANT records; no NULL-tenant/global fallthrough. Scope is fixed at registration, cannot be mutated by retry or epoch refresh and adds no business authority.

Server-owned capture contexts last at most5 minutes or the earlier identity/authority expiry. Reuse a scope within that exact verified actor/tenant/authority revision, parent and capture epoch; do not create a scope per operation. At capture retirement, no new browser batch may be accepted under that epoch. A sanitized batch already accepted by an authenticated attestor retains an immutable original scope envelope for background replay until the earlier of its parent expiry or48 hours from scope creation. This permits recovery of accepted server spools without extending browser/domain authority. The service verifies the attestor-authenticated scope; a replay cannot assign the event to a new actor/tenant. Parent revocation stops replay. A browser batch arriving only after retirement is rejected; its client timestamp cannot establish earlier acceptance.

Retain at most131072 scope records globally, separately accounted from parent registrations, with a minimum1024-byte charge per scope in the common1GiB metadata/event ceiling. They expire at their finite replay horizon; event rows retain scope snapshots afterwards. Scope capacity returns429/503 visibly and preserves existing records. Test at least600 sequential browser epoch rotations under one parent (over two days with a controlled clock), multiple components/tenants and capacity boundaries, without allocating600 parents or weakening the five-minute context rule. Server clock controls expiry; injected clocks test it, not shortened mandatory wall-clock acceptance elsewhere.

## Compilation manifests and safe vocabulary

The build runner mints buildId BEFORE compilation; component artifacts embed the supplied manifest. Browser startup supplies its actual buildId and a once-per-page execution runId. Java images/JAR resources, portal bundle metadata, CI artifacts and runtime manifests retain original IDs. A source fingerprint uses the exact `dkp-public-inputs-v1` algorithm below; a different SHA/fingerprint cannot silently inherit another build's manifest. Toolchain/dependency fingerprints and timestamp are recorded in the manifest. This is a reviewed reproducibility/provenance record, not a new code-signing or production-trust assertion.

An operator installs manifests using the private runtime/bootstrap tool with a canonical JSON file and an expected SHA-256 supplied from reviewed build evidence. No public manifest-upload route and no automatic download from caller URLs. Validate a strict schema, maximum1MiB per manifest, bounded class/frame/value catalogs and maximum4096 retained manifests. Input files must be private operator-owned regular files with no symlink/path traversal. The logging-owned bootstrap/CLI adapter validates the raw expected SHA-256 and schema before invoking its application install port; only its owned outbound SQL adapter writes the registry. Store immutable raw manifest bytes and parsed catalog in the dedicated logging database, with canonical normalized representation rather than a separate unaccounted durable file copy. Charge the FULL uncompressed UTF-8 manifest/catalog bytes plus at least1024 bytes of metadata against the common1GiB ceiling, reserving capacity in the same transaction as install. Maximum1MiB per manifest and4096 manifests are additional limits, not promises that all fit simultaneously. Missing capacity rejects install explicitly before publication. Active parent/scope references prevent reclamation. Do not accept a manifest merely because its filename equals a caller digest. A different reviewed build/vocabulary revision is a new immutable manifest. A parent cannot mutate its installed manifest; active references prevent premature reclamation.

The repository-owned vocabulary source supplies the16 initial Slice1 event codes. Extend it only with reviewed stable typed instrumentation events, never by uploading console text. Component-specific phase/dependency/error-code catalogs contain fixed reviewed identifiers; statuses, counts, sizes, durations and flags have bounded numeric/boolean types. Dependency versions/image digests must equal entries in the installed build manifest. Numeric runtime fields must not be used to serialize text/credentials. No arbitrary message or attribute map.

Generate exception-class and source-frame catalogs from the compiler's actual class/symbol/source maps plus reviewed dependency symbols; never from caught exception messages or incoming stack strings. Java class/method names and portal source-relative symbols are matched to that build's installed catalog. Unknown symbols are omitted and counted as `unregisteredSymbols`; do not register them dynamically from failed requests. Allow at most8192 class symbols and32768 frame/source entries per manifest and enforce the1MiB total bound as well. Long catalogs are not silently truncated: fail the manifest/build gate visibly or use a separately reviewed bounded catalog selection. Never include absolute developer home paths or source text. Classpath-generated catalogs are a diagnostic allowlist and do not confer caller authority.

Sanitize twice, before enqueue/spool and at common ingress. Invalid unregistered event/phase/version/code rejects the entire batch with a fixed code; raw exception/console text is never persisted. Producers map arbitrary console arguments to safe types/counts and explicit redaction markers, with typed instrumentation supplying actionable context. Drop/redaction/truncation counts remain visible. This prevents uncontrolled strings from being admitted merely by satisfying a regex. Tenant resource IDs require a separate explicitly approved typed field/catalog policy; none is introduced by this initial contract.

### Exact pre-manifest fingerprint algorithm

`dkp-public-inputs-v1` conservatively enumerates all tracked public repository inputs with `git ls-files --stage -z`, not just a guessed component subset. Include root/settings Gradle scripts, source, existing generated SDK source, schemas, public docs and every tracked dependency lock; dirty staged/working-tree content is hashed as it actually exists. Reject symlinks, non-UTF-8 or unsafe relative paths and unresolved/unmerged index stages. Use repository-relative POSIX paths and exact file bytes; no absolute workspace path or normalization of source text. Sort rows by UTF-8 path bytes. Each row is `{path,sha256,bytes,executable}` with exact content SHA-256, byte length and executable bit. sourceFingerprint is SHA-256 of UTF-8 RFC8785 canonical JSON of those rows. Record Git HEAD and whether tracked content differs from it separately; do not pretend dirty content was committed.

Before enumeration, reject nonignored untracked source/configuration outside explicitly declared build-output paths; stage intended new source before compilation. Generated output is kept untracked/ignored under component `build/` or `dist/` and the exact generated build-info output directory, never added to the input set. Reject a tracked generated build-info/manifest-output file instead of silently excluding arbitrary tracked source. node_modules, .git and private local-data are never compilation inputs or manifest payloads. Existing tracked generated SDK SOURCE remains an input; newly emitted runtime build-info/compiled artifacts do not. This prevents the manifest from hashing itself.

The builder writes the manifest only AFTER the pre-manifest input fingerprint and vocabulary/toolchain/dependency fingerprints are known. The manifest contains no hash of its own bytes or final artifact. Emit its raw-byte manifestSha256 and the completed artifact/image digest into a separate build receipt AFTER writing/embedding the manifest and finishing the artifact; do not feed that receipt back into the source fingerprint. Registration compares these independently captured digests. Test repeatable enumeration across worktree locations, dirty changes, mode/lock/source changes, generated-output exclusion, untracked-source rejection and no self-reference.

## Parsing, canonicalization and atomic receipts

Reject duplicate JSON property names, trailing JSON values, unknown properties, invalid UTF-8, nonfinite/unsafe numbers, malformed/nil IDs and invalid trace/span relationships before database dispatch. Encode wire integers within JavaScript's safe integer range. Maximum RAW HTTP body32768 UTF-8 bytes is enforced before parsing/canonicalization, independently of the sanitized canonical event8192-byte bound and32-event limit. A Beacon's transient token/epoch/envelope consumes that same raw32768-byte budget. Whitespace/escaping cannot bypass the raw input bound. Measure encoded bytes, not Java/JS character counts. No decompression or compressed request acceptance. Bounded parser depth16 and aggregate attribute/frame/event limits apply before arbitrary allocation. No raw body logging on parse failure.

Canonical event identity is SHA-256 of RFC8785 canonical JSON of the validated sanitized event plus the immutable trusted scopeId. Duplicate event IDs within one batch reject400 even if identical. `(producerId,scopeId,eventId)` is unique. Bind and validate the immutable parent/scope envelope BEFORE lookup; identical content in that same scope is idempotent, changed content within that scope returns409. Equal UUIDs in different authorized scopes are independent and cannot generate a global conflict/existence oracle. An accepted server spool keeps its original scope envelope; changing it is not a retry. A retained hash/receipt tombstone whose payload has expired returns410 LOG_EVENT_EXPIRED on ingestion, never COMMITTED or a recreated event. Reject the whole atomic batch if it contains an expired event; its authorized producer can reconcile bounded own-scope receipts and split remaining events before a bounded retry. Validation and insertion are atomic for a whole batch. HTTP200 ingest receipts contain only COMMITTED with receivedAt for each event, after successful SQL commit; unknown commit outcomes require replay or lookup. No persistence assertion from202, socket write or Beacon true.

Lookup receipts permit COMMITTED(with receivedAt), EXPIRED/UNKNOWN(without receivedAt). They expose no log body. A valid scope token restricts lookup to its original parent AND scopeId; an event outside scope is always UNKNOWN, indistinguishable from an unseen ID. Expired/revoked credentials never get a new receipt authority merely because records remain. An explicitly authorized operator can query retained events separately. Parent and scope horizons constrain admission/replay; receive time controls retention; client timestamp controls neither.

## BFF context and receipt ownership

Context POST requires the existing header-CSRF, exact Origin and active session checks. Body is strictly `{buildId,runId}` and at most1024 bytes. buildId must name an installed served portal artifact, not necessarily the newest artifact when an older tab is still valid; do not relabel it as the current compilation. runId is a validated diagnostic execution claim and does not select actor/tenant. Bind at most64 build/run entries per identity epoch and at most4096 entries globally, with explicit capacity rejection and expiry cleanup. Session transitions retire the epoch atomically. No browser bearer/producer/delegator credential is returned or durably stored.

Beacon and browser receipt requests require body-CSRF, exact Origin, live server epoch, bound build/run and `captureClass`. CURRENT_CONTEXT uses the verified scope kind (TENANT or AUTHENTICATED_UNSELECTED); UNATTRIBUTED permits only the separately sanitized pre-auth event vocabulary and never gains actor/tenant. A retired authenticated queue cannot be promoted into the new epoch or silently downgraded into pre-auth. Cross-tab requests retain their build/run and event-creation epoch. Already accepted server batches may replay their sealed original scope; new browser requests after epoch retirement fail403. Do not hold the session transition lock while waiting on HTTP/SQL: copy the validated immutable scope under lock, then dispatch outside it. That linearization defines acceptance under the old context; it cannot authorize business work.

The BFF chooses the original scope token from its finite epoch/build/run/capture-class bindings. The browser receipt body includes these identities plus at most32 unique event IDs, not a producer credential. The store checks scope on every lookup; unknown/out-of-scope IDs yield the same UNKNOWN result, so no unbounded per-session submitted-ID set is needed. Browser queues remain bounded by the original profile; receipts never gate UI. On an expired epoch browser persistence status stays unknown/expired locally until an operator query resolves retained evidence; never label it definitely lost or definitely persisted from expiry alone.

## Required specification fixtures and implementation proof

### Whole-request deadline and actual worker ownership — J1

The logging service admits at most32 concurrent logging requests with a dedicated32-worker executor and zero queued work. A single dedicated deadline scheduler has at most one live timer per admitted request and removes cancelled timers. Admission exhaustion rejects immediately with429 LOG_RATE_LIMITED; it never allocates an extra worker or waits on an unbounded queue. The five-second monotonic deadline begins at logging-route admission and includes authentication, bounded body parsing, dispatch, connection acquisition, SQL and the response decision. Pass the same remaining deadline inward; no layer starts a fresh five seconds. The BFF retains its separate selected2-worker/16-queued profile and its original total deadline including queue time.

The scheduler performs only a bounded nonblocking state/completion decision. It MUST NOT run JDBC, authentication, body parsing, cleanup, blocking response writes or arbitrary synchronous completion callbacks. Keep its completion primitive private and expose a single-consumer request handle, rather than an externally extensible future whose callbacks can execute on the timer thread. Response serialization/writes belong to the separately bounded HTTP transport. Health and authenticated observer-control paths have independently bounded execution and do not acquire an ingestion worker; exhaustion must not prevent reading in-memory health or refreshing a trusted volume observation.

An independent deadline response completes with503 LOG_STORE_UNAVAILABLE by that deadline when no committed result is available. It is an UNKNOWN persistence outcome, not proof of rollback or loss. JDBC work and cleanup may still outlive this response. Timeout, client disconnect, response cancellation or an interrupted observer MUST NOT release the admitted worker slot: retain it until the actual task and its finally cleanup exit. Late worker completion cannot overwrite an already completed/cancelled response with COMMITTED. Expose bounded in-memory active/deadline/degraded health without recursive SQL/logging. If all workers remain occupied after deadline, subsequent admissions stay rejected; never manufacture spare capacity. Shutdown signals cancellation and reports remaining workers honestly; it does not claim that all JDBC work has terminated.

Also configure finite pool/driver connection acquisition and remaining-budget JDBC network/statement/lock limits before each potentially blocking step, including configuration, commit and cleanup. A fixed socket timeout alone is insufficient: the pinned driver bounds individual reads, allowing a slow sequence of reads or blocked writes to exceed a whole-request deadline. The independent response boundary does not replace these I/O controls or permit unbounded background threads. Real verification must cover pool exhaustion, stalled authentication/SQL/configuration/commit, trickled database responses, cancellation, late successful commit and shutdown, while the same32-slot bound holds through actual worker exit. Executor unit tests alone do not close J1 or authorize transport wiring.

If the original deadline has expired, no positive business budget remains: never start COMMIT, another business query or a retry. Give rollback/abort/close a separate cleanup-only elapsed budget of at most2 seconds, with positive finite remaining network/driver limits (never0/disabled). Do not begin another cleanup attempt after this tail expires. A driver or OS call can still fail to return despite configured limits; then mark the request/worker degraded and retain its original admission slot until the actual call and finally exit. Neither the response deadline nor cleanup-tail expiry proves physical JDBC termination or non-persistence. No replacement cleanup workers, unbounded queues or new business/commit budget are created to hide a stuck call.

### Owned volume admission and bounded BFF work

The trusted external runtime observer measures the actual dedicated PostgreSQL data volume, using only the exact owned runtime identity and a2-second command deadline. It authenticates to the private storage-observation endpoint with a separate observer-only credential and the configured volume identity. Service receive time establishes freshness; no client timestamp or arbitrary volume/path/URL controls admission. Validate nonnegative free space not exceeding total. Keep one bounded latest observation in memory; missing/stale/failed observation rejects ingestion as specified in design.md. No Docker socket or raw PostgreSQL data mount is introduced into the application. The health update itself cannot depend on DB writes or recursively emit events. Monitor/runner failure remains visible through independent health state and bounded sanitized pending events.

BFF logging uses a dedicated bounded executor with2 workers and16 queued dispatches, a5-second total request/forward deadline and immediate explicit429 on admission exhaustion. It must not wait for log network/disk under the session transition lock or consume unbounded business-request workers. Preserve existing business ingress/resource controls; reconcile route accounting in the applicable reviewed ingress contract before wiring this endpoint. Full request byte/parse bounds and authorization precede allocation/forwarding. Business operations never await logging completion. Tests saturate/delay the logging path while a real unrelated UI action progresses; generic fire-and-forget source code alone does not prove isolation.

Version fixtures for two same-SHA compilations, repeated runs, valid/invalid identities, duplicate properties/IDs, byte limits with multibyte strings and envelope overhead, canonical same-content retry, same-scope changed-content conflict and independent equal IDs across isolated scopes, commit-only receipt and conditional lookup time, all scope kinds and wrong authority/tenant, stale tabs, multiple tabs, expired/revoked grants, parent/scope churn/caps, unknown vocabulary, raw secret/document injection and known/unknown source frames. Schema fixtures prove syntax only; real PostgreSQL, browser, authority and parser tests prove semantics during implementation. Contract lint/SDK compatibility and independent exact-revision review precede transport/runtime source. No fixture replaces the mandatory real same-store two-build FE/BE/infra acceptance, delayed Beacon UI test, pinned coverage/CI/dev/post-dev gates.
