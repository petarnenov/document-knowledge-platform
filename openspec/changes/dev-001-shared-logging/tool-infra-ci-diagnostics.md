## Pure diagnostics port and original provenance

Keep diagnostic event construction separate from Docker/HTTP/filesystem/registration authority. Tools receive an explicit narrow emitter/context; their domain/resource decisions stay in their existing modules. A no-op or bounded in-memory test emitter is permitted for unit tests, not as evidence of continuous-development adoption. Never intercept global subprocess functions, replace stdout globally or introduce hidden global caller identity.

The original tool distribution gets a buildId before compiling/packaging, using the existing public-input fingerprint, original manifest and receipt helpers. Compile with the pinned Python runtime, embed the original manifest and registered vocabulary/catalog, seal the actual distribution and validate installed bytes before launch. Derive owned exception/frame/source symbols from the compiled public sources; unknown concrete symbols are omitted/countable, never replaced with invented names. Normal interpreted source/tool commands retain their sealed source-distribution identity; a tool wrapper's buildId must not be presented as the compilation identity of the child Java/Node/vendor artifact it observes. Existing child manifests retain their own buildId/digest/source revision; link the invocation by validated correlation, preserving original IDs/timestamps through replay.

Each execution has a distinct runId/instanceId and correlation context. Configuration binds the original artifact/manifest, permitted component, endpoint, private producer-only grant and bounded spool using the already reviewed SDK semantics. Runtime launch cannot manufacture new build identities or label the current checkout as an old artifact. Missing/mismatched configuration is visibly degraded/invalid; it cannot silently establish working adoption. Refuse an unregistered vocabulary rather than adding captured exception text to a catalog.

## Actual tool diagnostics and safe failure capture

Use existing closed event names/phases and typed diagnostic fields. Register finite public stage/operation/error codes in the original manifest. Emit DEBUG/TRACE for useful successful as well as failed stage boundaries, duration, attempt, configured safe resource identity, bounded resource/count measurements and actual cleanup outcome. Capture a Throwable/Python exception immediately before mapping it to the public safe error or UNDETERMINED boundary. Preserve registered concrete class, bounded cause/frame/source information and caller correlation; absence of sufficient evidence remains UNDETERMINED. A later passing run cannot rewrite an earlier failure.

Do not capture command lines, arbitrary environment variables, HTTP headers/bodies, raw SQL, uploaded content, document names/paths, credentials, cookies, private certificates/keys, raw stderr/stdout or exception messages. Public inventory phase/error codes identify the command/stage without retaining its private arguments. Sanitize against the original catalog before buffering and revalidate at ingestion. Original command results, deadlines, tenant checks, security assertions and cleanup ownership remain authoritative.

SDK enqueue remains bounded and nonblocking; logging failure never replaces the business failure, retries a mutation or recursively logs. Use existing SDK event/batch/queue/spool bounds and visible counters. Only its delivery worker handles network I/O. A finite CLI may perform a bounded explicit finish/receipt check after its real work, without changing the real command exit code; delivery result remains separately COMMITTED/PENDING/UNKNOWN/REJECTED. Repeated or interrupted import preserves exact source event IDs and bytes. Do not claim pending0 proves disk-empty or shutdown durability.

## CI and offline import

Cloud CI has no assumed route to developer loopback and receives no local operator/reader/registrar credential. Use the same reviewed command interface locally and in workflows. CI collects only already sanitized closed-schema events with original manifest/build/run/source identities into a bounded explicit offline bundle and publishes it through the existing pinned artifact action, even when the business check fails. Never include private runtime directories, raw process logs, producer tokens or fixture authority. The manifest and events are untrusted input on download; artifact presence means PENDING_IMPORT only.

Define the exact closed bundle schema, entry/path/count/byte limits and rejection fixtures before its parser. Preserve original source-generated UUIDs/timestamps and manifest bytes. Bind source revision, workflow/job/check identity and original artifact hashes in the evidence receipt; verification must detect changed events/manifests, unknown fields, duplicate paths/keys, incompatible identities and unbounded input before allocation. CI metadata supplied in an artifact grants no registration or tenant authority.

An explicit trusted local importer verifies the selected downloaded artifact/source/run and original manifests, then uses existing operator-controlled manifest installation and finite producer registration for the exact authorized original component/build/run scope. It never derives authority from the artifact or posts arbitrary URLs; it uses the configured SAME common endpoint and existing TLS/tenant checks. Journal registration outcomes before network mutations; unknown outcomes require reconciliation rather than blind retries. Producer-only ingestion then replays the exact validated source events, with scoped receipt batches within the existing limit. Persist a sanitized import receipt with original artifact digest, exact IDs, COMMITTED/PENDING/UNKNOWN states and actual endpoint identity. Retry is idempotent; conflicts remain visible and original failure receipts are immutable.

No remote route, Actions secret or repository token is required for producer delivery. Authorized artifact retrieval is separate from local producer authority. Workflow checks may pass their real function with pending telemetry, but #457 final integration requires actual import and independent common PostgreSQL/viewer/scoped-receipt evidence for the exact CI run. Uploading a spool alone never satisfies that gate. Test normal interruption/restart, unavailable destination and recovery; defer sustained capacity/pathological faults as already authorized.
