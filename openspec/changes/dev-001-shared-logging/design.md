## Context and authority

Owner #457 requires one persistent shared logging destination for all builds and components, mandatory build filtering, development verbosity and nonblocking frontend Beacon. Public System Design §12.5 selects centralized telemetry and OpenTelemetry trace/correlation propagation, with audit separate. This change implements a development telemetry persistence boundary; it does not replace authoritative audit or grant content-access authority. Existing tenant checks, untrusted-content restrictions, runtime resource ceilings, operation deadlines and isolated test networks remain controlling.

Status: proposed development selection, awaiting independent review and an exact-revision recorded selection. Every numeric profile below is NEW and must be reviewed before runtime changes. No architecture/security-control/CID or production sign-off is inferred from artifact completion or standing development approval.

## Proposed dependency and ownership boundaries

Introduce `services/dev-logging/{domain,application,adapters-in,adapters-out,bootstrap}` using the existing Java25/Micronaut conventions. Domain/application contain framework-free event, authority, persistence/query and delivery ports. PostgreSQL and HTTP/OTel integrations live in adapters. `modules/observability-support` exposes framework-free producer records, redaction and nonblocking emitter ports; framework-specific logging bridges stay in adapters/bootstrap. It cannot depend on domain applications or turn business code into an HTTP/SQL client. Extend architecture graph tests, including forbidden-dependency tests, with the reviewed boundaries.

Only the logging service's outbound SQL adapter has credentials to its dedicated logical PostgreSQL database `dkp_dev_logs`. Domain services, workers, frontend and infra have no direct SQL access. Keep telemetry tables and migrations outside domain/audit databases. Reuse the repository's reviewed PostgreSQL18.6 immutable image digest and dependency pins; independently review any new dependency or pin. The shared runtime owns its persistent volume and explicit operator lifecycle; normal task start/stop, fixture deletion and worktree cleanup cannot stop or delete it. Tests may have disposable isolated fixture databases, but those cannot prove the common-store acceptance.

All writers use the same canonical ingestion protocol. Browser access is a same-origin BFF adapter forwarding that protocol to the common service, not a second database. Services/workers can send directly; isolated processes keep their network restrictions and emit a bounded structured spool for an external authorized runner to import through that API. OpenTelemetry fields map to the standard logs data model (`Timestamp`, `ObservedTimestamp`, severity, resource/service identity and trace/span IDs). The application owns a framework-free ingestion port; HTTP and future Collector/OTLP mapping are inbound adapters to that same port/store. Preserve source IDs, original timestamps, server receive time, severity, service/build/run resource attributes and trace/span context across that mapping; reject missing or conflicting provenance rather than invent it. Actual Collector deployment, exact dependency/pin/topology, mapping conformance and security verification remain explicitly OPEN under #47/BP15 before that runtime implementation and BP15/full-project closure. #457 implements the immediate development API/store incrementally; it does not claim Collector or complete observability delivered. Independent scope review confirmed this sequencing against the actual #457/#47 criteria and System Design §12.5; no architecture or security gate is waived.

## Provenance and event contract

The versioned wire definition will be `contracts/openapi/v1/dev-logging.yaml`, derived from the draft contract in this change and validated/generated with existing contract tooling before publication. Add independent valid/malformed fixtures and SDK drift tests. `contracts/dev-logging/v1/README.md` documents producer registration, build manifests and protocol semantics. No unversioned permissive JSON endpoint.

A coordinated compilation mints one UUID `buildId` before building its artifacts; independent component compilations mint their own build IDs even at the same SHA. Record component, Git SHA, dirty-source fingerprint where applicable, dependency/toolchain fingerprint and build timestamp in immutable build metadata. Never recompute an artifact's buildId at startup or overwrite provenance with the current checkout. Source builds lacking an explicit generated manifest fail the development logging gate visibly. Each runtime execution mints a distinct UUID `runId`; component instances add `instanceId`. Runtime and CI records reference the actual build being executed; unrelated prebuilt images retain their original artifact build IDs and can link the coordinated invocation through correlation metadata.

Each event has `schemaVersion:1`, UUID `eventId`, `buildId`, `runId`, `instanceId`, `component`, 40-character lowercase `gitSha`, source fingerprint, UTC `timestamp`, `severity` (TRACE/DEBUG/INFO/WARN/ERROR/FATAL), stable `eventName`, required `correlationId` and optional W3C-compatible lowercase hexadecimal `traceId`/`spanId`. Standalone startup/build events use a newly minted operation correlation ID, never a fake HTTP request. Optional structured phase/outcome, duration, attempt, deadline, status, dependency/version, error and approved attributes carry technical context. The server adds `receivedAt`, authenticated producer identity and authoritative tenant/actor attribution. Producer timestamp is untrusted, cannot govern retention, and its skew remains visible. `buildId` and source fingerprints are diagnostic claims bound by registration to the producer; they never grant tenant or content authority.

Persist events in a logging-owned table with a database-generated monotonic sequence, server receive time, provenance columns, trusted scope and bounded JSON details. Unique `(producerId,scopeId,eventId)` provides scope-isolated idempotency: identical retained content within the same scope returns committed; changed content within that scope returns conflict. Equal UUIDs in different authorized scopes are independent and cannot reveal one another through conflict status. A live tombstone for an expired payload returns410 LOG_EVENT_EXPIRED on ingest, never a fresh persistence acknowledgement. A batch is validated and committed atomically before HTTP200 acknowledges persistence. No202 means committed. A connection failure after COMMIT means unknown until idempotent replay/receipt lookup resolves it. Retained tombstones must preserve deduplication for the documented replay window; expired events are reported expired, not silently re-created by old spool replay.

Indexes cover `(buildId,receivedAt,sequence)`, `(runId,receivedAt,sequence)`, `(component,receivedAt,sequence)`, correlation/trace and trusted tenant plus time. Queries have bounded stable keyset pagination scoped to the reader's grant and server-side filter binding. Global sequence values are internal SQL state: never include them in StoredEvent responses or readable cursor contents. A signed/base64 cursor alone does not hide its contents; use authenticated encrypted cursor contents with reader/filter/expiry binding. Test interleaved events from two tenants to ensure the first tenant cannot observe the other's sequence gaps. Filter by build/run/component/severity range/time/correlation/trace; no arbitrary SQL or unrestricted text expressions. A reader cannot obtain global counts, cursor hints or event existence outside its grant. Operator-wide reads require a separate explicit development operator grant.

## Authentication and Beacon trust

Local services, workers, infra importers and Collector adapters use generated scoped producer credentials stored outside tracked files. A producer grant fixes permitted component(s), build/run registration and tenant scope; it cannot mint an arbitrary actor/tenant or read logs. Separate operator/read credentials control query/receipt visibility. Shared-service bind defaults to local/private development networking; remote CI requires an explicitly configured authenticated HTTPS endpoint. No automatic public exposure or baked-in/shared default secret.

FE uses `navigator.sendBeacon('/api/v1/dev-logs/beacon', Blob(JSON, application/json))`, never await/fetch as an ingestion replacement. The BFF reads a bounded body only after validating the active session and exact allowed Origin; a narrowly scoped body `csrfToken` is constant-time compared against the current session token before forwarding. Reject duplicate/malformed framing, unknown envelope fields, unauthorized source bindings and oversized bodies. Existing mutation endpoints retain their required X-CSRF-TOKEN header. Any framework CSRF exception is path/method-specific to this endpoint, with equivalent body+session+Origin verification and explicit negative integration tests; no global CSRF bypass. Strip the token before enqueueing, forwarding, error output or persistence. The service only accepts a BFF-authenticated delegated scope; browser-supplied actor/tenant values are forbidden.

The BFF creates a random server-owned `contextEpoch` through POST `/api/v1/dev-logs/context`, guarded by the existing session+exact Origin+X-CSRF-TOKEN mutation checks. Its bounded JSON body supplies diagnostic `buildId` and `runId`; the former must match a registered served portal artifact and the latter is the UUID minted for that browser execution, never a credential. Store the identity epoch with immutable verified actor, selected tenant (possibly absent) and current session identifier. Bind each accepted browser build/run to that epoch through a separate finite registration; tabs may share the identity epoch without replacing one another's execution IDs. The no-store response returns only epoch, bound build/run and expiry. Expiry is the earlier of five minutes or session expiry. An unchanged identity context retains the same epoch until expiry; login/tenant selection/logout/session expiry/BFF restart retire it atomically. A replacement epoch cannot adopt pending events from its predecessor. No identity-contract JSON fields or business security semantics are widened. Exact bounded registration, delegation and receipt rules are in `producer-protocol.md`.

The browser captures that epoch at event creation. Every Beacon AND receipt lookup must match the live server-owned epoch and original artifact/run binding; the BFF checks it under the session transition lock before delegation. A delayed old-tab event with the new tab's shared current cookie/CSRF but the old epoch is403 and cannot be stamped as the new tenant. An event already accepted and sanitized by the BFF before retirement keeps its original trusted attribution and finite server replay envelope; retirement cannot relabel it. Browser queues cannot relabel events on refresh: an expired epoch's unaccepted events become explicitly EXPIRED locally. An authenticated session before tenant selection has explicit `AUTHENTICATED_UNSELECTED` scope (verified actor, no tenant), visible only to an operator; never fabricate a tenant or silently treat its events as anonymous. Client diagnostic claims never become business authority.

For pre-auth events, persist only a separately marked `UNATTRIBUTED` capture class containing no actor/tenant/resource IDs. Once a current context is available, the BFF can forward those events with server `scopeKind=UNATTRIBUTED`, no actor/tenant, and operator-only query visibility; it must not infer the later actor was the earlier actor. A retired authenticated queue cannot be downgraded/replayed as unattributed: capture-class/epoch remains fixed locally, and the server only permits the narrowly sanitized pre-auth event vocabulary under this class. If no session can be established, keep delivery visibly pending or lost at the browser's finite bound, never claim database persistence. Test stale tabs, shared cookies, refresh races, identity retirement before dispatch and receipt isolation. Ordinary portal users cannot query global telemetry; browser receipt checks expose only IDs submitted through their current epoch and no log contents.

## Useful diagnostics and sanitization

Development DEBUG/TRACE is enabled across every implemented producer, with stable typed events at successful and failed boundaries. Coverage includes FE console/error/unhandled rejection, HTTP/query/mutation start/end/cancel, route and identity transitions; BE request/operation/admission/state/DB/provider start/end/retry/timeout/cancel/cleanup; worker lifecycle/dependency outcomes; infra/build/test/CI startup/version/exit/readiness and owned resource actions. Automatic bridges supplement meaningful typed events rather than replacing them with generic ERROR-only records. Inventory every current executable/service and enforce registration/instrumentation for future additions.

No raw console objects, Throwable.toString, exception message, headers, URLs with parameters, SQL statements/bindings, document names/bodies, arbitrary absolute paths or request/response bodies. Use approved message templates and bounded allowlisted structured values. Preserve exception class, safe error code/SQLSTATE/HTTP status, bounded cause classes and source-relative symbol/file/line frames; raw message strings can contain document text and are not inherently safe. Arbitrary console arguments are summarized by safe type/count and explicitly redacted when not an approved structured diagnostic. Stable opaque resource/request identifiers may be retained only within authorized tenant scope. Redact before memory/spool and independently revalidate/sanitize at ingestion. Neutralize control characters and render values as text, never executable markup. Do not serialize logger failures recursively. Include sanitizer/truncation metadata without repeating the rejected value.

## Proposed bounded development profile

These are implementation selections for review, not final resource/headroom measurements. No sampling of ordinary successful events is enabled silently. Emit explicit counters when bounds prevent capture.

- Event: at most8192 UTF-8 encoded bytes after sanitization,32 allowlisted attributes, exception causes4 and frames32; record truncation metadata. Unknown schema/fields or invalid identities reject instead of accepting incomplete provenance.
- Browser batch: at most32768 UTF-8 bytes and32 events, enforcing both limits. Flush asynchronously every1000ms or at16 pending events and on visibility-hidden/pagehide without synchronous unload work. Queue cap512 events/1MiB; sanitized IndexedDB spool cap4MiB with explicit oldest-drop/loss counters. No credentials or CSRF tokens in durable spool. Send failures use bounded jittered retries1s..30s while the page is active; no busy-loop/unbounded timer. Receipt reconciliation is separate, asynchronous and cannot gate UI.
- Other producers: bounded queue2048 events/8MiB, single background dispatcher, batches at most32 events/32768bytes; bounded disk spool64MiB per producer with visible reject/drop and no unbounded worker/thread creation. Logging methods never wait for HTTP/DB/disk on a business call. Emitters spend only bounded CPU on serialization/sanitization; background-owned disk writes must not conceal unspooled crash-loss risk.
- API: authenticated per-producer token bucket256 events/second with burst1024; maximum32 concurrent ingestion calls, bounded request32768bytes and total operation deadline5s. Full body/records validated before commit; overload429, malformed400, auth401/403, conflict409, oversize413, unavailable503. Fixed error codes only. Health/readiness do not claim pending batches persisted.
- Query: at most200 rows per page, default50, bounded time window24h per request and5s deadline. Filters cannot expand authorization. Cursor validity15min and filter/reader binding; query/logging requests suppress automatic self-observation loops while updating bounded nonrecursive health counters.
- Store: proposed seven-day retention by server receive time; at most1GiB of conservatively accounted event/dedup state, charging each row at least1024bytes plus retained sanitized payload bytes. Delete oldest eligible telemetry in bounded1000-row transactions and record retention/size deletion counters. Removing a payload before its producer replay horizon retains its hash/receipt tombstone and its reservation; never evict a live tombstone to admit a new event. If reclaimable capacity is insufficient, reject new ingestion503 LOG_CAPACITY_EXHAUSTED explicitly. This is NOT a physical PostgreSQL/WAL/disk size guarantee. Before accepting a batch, require a fresh (at most5s old) volume observation with at least2GiB AND10percent free space on the logging-owned volume; missing/stale/failed observation or a lower threshold rejects ingestion503 LOG_DISK_UNAVAILABLE. Use a bounded single observer with a2s deadline; no fallback to assumed free capacity. Migration/startup must establish the same preconditions. PostgreSQL has explicit reviewed WAL/checkpoint/storage settings and volume monitoring; their real physical behavior is a test gate, not inferred from payload accounting. Maintenance runs one transaction at a time, at most1000 rows and2s statement timeout, without unbounded drain/retry loops. Loss counters and last-known degraded reason use bounded independent health state so a broken database can still report its failure.

### Finite registration, replay and deduplication

An operator registration binds an immutable producer principal to its component, build/run/source identity, allowed trusted scope and a server-created validity interval. No arbitrary client registration or permanent default producer. Registration lifetime is at most48h; expired/revoked principals reject all new ingestion and replay and cannot be renewed/reused to import an old spool. New runs/registrations use new producer IDs; imported spools preserve their original IDs/grants. Rotation cannot reissue a previous producer ID or extend its old replay horizon. Events are admitted only while that principal is valid, regardless of a client-supplied event timestamp. Browser delegation is additionally bounded by the live session epoch, not this48h maximum.

The deduplication key and sanitized canonical-payload hash remain durable until the later of normal event retention and registration `acceptUntil+15min`. Payload size eviction can replace a record with its bounded receipt/hash tombstone, without releasing its reserved dedup capacity before that horizon. Once a principal expires, all late spool replay is terminal EXPIRED and cannot recreate a UUID after its tombstone is reclaimed. Receipt lookup outside the retained horizon returns EXPIRED/UNKNOWN without asserting historical absence. Immutable event rows retain their trusted scope snapshot and producer identity without depending on a live registration join. Separately bound parent registrations and ephemeral delegated scopes as specified in `producer-protocol.md`; an identity epoch is not a new parent producer. All retained metadata and tombstones consume the same accounted store ceiling. Reject registration/admission explicitly at capacity; never evict a live replay reservation. Use server time for lifecycle decisions and test continuous epoch rotation, size eviction, unknown-commit recovery, expired spool and ID/grant reuse.

### Third-party runtime provenance

Do not manufacture a project compilation identity for vendor images. Infrastructure observation events use the real DKP wrapper/observer compilation buildId/runId; their dependency context records the observed immutable vendor image digest and version, with vendor compilation provenance explicitly UNKNOWN unless actually supplied and verified. Project-built images retain their own actual embedded manifests. This distinguishes the observer from the observed component without inventing vendor Git SHA/buildId or discarding useful provider diagnostics.

## CI, isolation and common-store delivery

Every compilation/test invocation declares endpoint, producer credential reference, build manifest and spool ownership. Direct CI ingestion requires a reachable authorized endpoint proven from the actual runner. If absent, retain a bounded sanitized NDJSON spool as a private artifact and mark `SHARED_STORE_DELIVERY_PENDING`. An authorized operator importer replays the original event identities/provenance into the SAME persistent store, verifies committed receipts and then marks delivery complete. Artifact upload alone is not acceptance. Do not weaken a network-none test container, expose the Docker socket or send private evidence to public artifacts. A trusted external runner can ingest safe structured records from isolated checks, not unrestricted logs/document fixtures.

Actual credentials/reachable shared hosted-CI endpoint are external configuration, not facts this spec can invent. Implement/test local shared runtime and the import route independently; report any remaining CI configuration/delivery gate explicitly. At least one real CI spool must be imported and queried from the common store before #457 closure if direct connectivity is unavailable.
