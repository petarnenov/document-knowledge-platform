## Private immutable grants

Additional required properties when enabled: `writer-password-file`, `registration-grants-file`, `observer-grant-file`, `volume-identity`. Reuse the bounded owner-only regular non-symlink file reader, including before/after identity/permission checks; never read credentials from JSON requests, images, CLI values, logs or browser assets. Writer password follows the existing opaque32..512 ASCII profile. Volume identity is exactly64 lowercase hex; no path/URL supplied by HTTP.

Registration grants are strict UTF-8 JSON, duplicate/trailing/unknown/null/type rejection, depth8, at most1MiB. Root exactly `{schemaVersion:1,registrars:[...],delegators:[...]}`, at most4096 of each. Registrar entries exactly `id,expiresAt,tokenSha256`. Delegator entries exactly those fields plus `parents,bridgeManifests,permissions`, each bounded4096 unique values. IDs are canonical nonnil UUIDs; hashes/manifests lower64hex; expiry is strict RFC3339 UTC with explicit future validity. Permission entries contain `kind` and only the issuer/tenant fields required by the existing ScopePermission constructor; no subject authority, wildcard or inferred parent/build/tenant permission. Empty catalogs or sets grant no authority. Construct existing immutable Registrar/Delegator/ConfiguredLogRegistrars values; no authority derived from route bodies. Fixed failure code only.

Observer grant is separate strict UTF-8 JSON, max4096bytes/depth4, exactly `schemaVersion:1,id,expiresAt,tokenSha256`, same canonical ID/hash/expiry rules. One observer-only grant, service receives its hash only. Reader, registrar, delegator and observer IDs/hashes must be pairwise disjoint at enabled startup; check all configured entries, including otherwise unused grants. Producer authentication additionally rejects any configured nonproducer credential hash before SQL authentication, preventing role reuse even if a stored producer hash collides. Tokens have the existing opaque43..512 URL-safe format and constant-time digest comparison; expiry always rechecked against server Clock. New producer credentials remain cryptographically random and scoped by SQL. No role gains query, registration, delegation or observer authority through another role's token.

## Effective writer privileges

Add an outbound JdbcWriteRoleVerifier and owner-run SQL provisioning resource, exercised first ONLY in disposable owned PostgreSQL. Require exact database/role, CONNECT and dev_logs USAGE; no superuser, role/DB creation, replication, bypass RLS, inherited/member roles, database CREATE/TEMP or schema CREATE. Reader privileges stay unchanged. Application writer has exactly:

- SELECT on capacity, manifests, producers, scopes and events.
- INSERT on producers, scopes and events.
- Column UPDATE only on capacity.reserved_bytes, producers.revoked and scopes.reserved_bytes. PostgreSQL row-locking SELECT FOR UPDATE/SHARE needs UPDATE privilege; the scopes column grant supports the existing `FOR SHARE OF p,s` without granting credential, identity or tenant updates. No new application mutation of scope reservations is added.
- USAGE on the events identity sequence only; no sequence SELECT/UPDATE.

Reject effective excess table OR column permissions, including PUBLIC/inherited grants, event UPDATE/DELETE/TRUNCATE, manifest INSERT/UPDATE/DELETE, scope credential/identity UPDATE, other dev_logs tables and schema_migrations access, other sequences, grant options and ownership. Reject missing required privileges. Real tests must prove the current row-locking transactions work with this exact role, rather than using an owner role and assuming DML suffices. No blanket ALL/table UPDATE or owner/admin fallback. Writer role does not perform retention or schema migration; those remain separate owner-controlled operations. Existing V1 DDL and additive V2 bytes are immutable. Actual V1-to-V2 runtime tooling, schema-shape/digest versioning, private file generation and controlled shared activation are the following integration step, not implied by this assembly check.

## Independent in-memory observer control

Implement the existing POST `/api/v1/dev-logs/storage-observation`, conditional on explicit observer authentication and the configured observation port. Keep this handler outside both blocking logging worker pools. Its bounded work is dedicated credential hashing, strict UTF-8 JSON parsing (max1024 raw bytes, depth4, duplicates/trailing/unknown/null/types rejected), deadline checks and one atomic in-memory update; never JDBC, filesystem, network, Docker, logging recursion or blocking executor dispatch. No arbitrary callbacks on a deadline scheduler. Use the route-admitted deadline without creating another budget. Runtime global32768-byte bounds remain; observer adds its tighter bound. Concurrent handler admission is fixed at2 with immediate429 and no queue; release only after handler exit.

Authenticate the single Bearer before custom parsing. Body is exactly volumeIdentity/freeBytes/totalBytes, no URL/path/timestamp/extra authority. Reject query parameters, compression, non-JSON, unsafe/noninteger values, negatives and free>total; total1..9007199254740991. Wrong volume403 cannot invalidate an existing trusted observation. For the authenticated configured observer, invalid numeric observations invalidate admission as existing ObservedVolumeAdmission specifies; malformed requests never install observations. Return204 only for accepted in-memory observation, never a database receipt. Fixed400/401/403/413/429/503 and no-store/nosniff omit sensitive values. Missing, stale>5s, backward-clock or insufficient-space observations continue to reject ingestion; no startup assumed-free fixture in actual assembly. No new public health API in this slice; existing bounded in-memory health remains available to owned composition/tests.
