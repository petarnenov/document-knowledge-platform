The fixed component is runtime-tools. Mint the tool buildId before source enumeration/compilation; preserve original gitSha, dirty flag, input fingerprint, manifest and artifact receipt. Do not relabel a later checkout or a separately compiled SDK as this tool. The independent SDK build/manifest remains separate and is not installed by this slice.

The sealed public source tree contains exactly the prepared tracked public inputs, preserving repository-relative layout and executable flags. It contains no Git metadata, untracked files, node_modules, ignored/generated build outputs, credentials or private local-data. Maximum4096 files, each at most4MiB, total source bytes at most32MiB, source path at most256 UTF8 bytes; reject canonical path/link/ownership violations before copying and recheck prepared inputs afterward. These are explicit first-distribution bounds, not relaxations of the existing manifest helper's stricter checks.

Their source provenance is retained; unregistered runtime failure symbols remain omitted/countable. This distinction preserves the broader rank4 inventory obligation.

## Fixed compiler and original catalog

Use pinned CPython3.14.10 Linux/amd64 from the existing immutable Python image, nonroot readonly/network-none/no-caps owned container with finite memory/PID/time limits and operation journal. Input source and compiler are readonly; only fresh private output is writable. Do not execute provider or domain code during compilation. Compile each fixed module to checked-hash pyc with its public relative source path as dfile, optimization0, preserving the existing SDK magic/header/source-hash checks. Record compiler image/version, source SHA, pyc SHA/bytes/magic and actual source filename. Retain failure evidence and remove only the exact owned terminated compiler container.

Traverse each compiled module code object's co_consts recursively in index order. A code locator is a list of integer constant indices from the module root (empty list for root); at most32 levels and32768 total code records. Each code record contains exactly module, locator, qualname, firstLine, symbol, source. Symbol is the declared module alias plus a dot plus co_qualname plus a dollar plus locator integers joined with dots (ROOT for empty locator); source is the public relative path. Require symbols to satisfy the existing closed frame vocabulary and be unique. No filename guessing, AST execution or catalog learning from a caught exception. Build vocabulary frames directly from these records. The compiler record has schemaVersion1, python, magic, modules; each module row has name, source, sourceSha256, compiledSha256, compiledBytes and frames. Reject unknown fields, duplicate locators, missing code objects or source/code filename mismatch. The complete canonical compiler record is at most4MiB.

The fixed tool vocabulary includes existing common event names, selected provider checkpoint/DM phases and error codes from python-tool-port.md, plus the thirteen successful DM phase names PROVIDER_JOBS_DM_ followed by each existing phase value (future scopes remain unimplemented). Declared owned exception class is dkp_provider_jobs.AcceptanceFailure only; known pinned runtime types are builtins.ValueError, builtins.OSError, builtins.RuntimeError, builtins.KeyboardInterrupt and builtins.SystemExit. Other concrete classes remain unknown until an explicit future catalog/binder extension; never substitute a superclass. Compiler frames and these fixed classes extend only the original manifest vocabulary before sealing. No producer grant or runtime authority is in the catalog.

## Sealed artifact and closed verification

Produce one ZIP_STORED archive with no archive/member comments, encryption, extra fields, links, directory records or duplicate names. Entries are sorted UTF8 names, fixed DOS timestamp1980-01-01 and Unix regular-file mode0444 or0555 according to original executable flag. Limits:64MiB entire archive, at most4101 entries, source members bounded as above, each compiled member at most2MiB and complete compiled output at most4MiB, original manifest at most1MiB and compiler record at most4MiB.

Members are exactly source/<each prepared input>, compiled/provider-jobs.pyc, compiled/tool-diagnostics.pyc, manifest.json, prepared.json and compiler-record.json. prepared.json uses the existing prepared record (maximum32MiB under its current reader bound); all original input rows/bytes/modes must match the source members. Manifest bytes are the original finalized canonical bytes, not regenerated with a new time/buildId. Its vocabulary must exactly equal the fixed declared vocabulary plus extracted code records; verify existing fingerprint/preparation/dependency/toolchain associations. The external original finalized record and sealed receipt retain compiler association and the exact artifact hash/length; archive construction then existing seal must recheck the original checkout unchanged. No new schema version or upload acceptance contract is introduced.

The verifier takes explicit expected original buildId, manifest SHA, artifact SHA and compiler-image identity from trusted build evidence. Artifact metadata cannot confer authority on itself. Bound regular canonical input before parsing, reject duplicate JSON properties/nonfinite values and exact-key/type/bound violations. Validate complete ZIP inventory and original source content/modes, original prepared-input fingerprint, manifest/catalog equality, pyc hashes/headers/source hashes and every code locator/descriptor against loaded original compiled code before returning verified original facts. Never import/execute either compiled module during verification. Reject altered source, modes, bytecode, catalog, original manifest, unknown/duplicate members, links/traversal and incompatible compiler version. A passing verifier is provenance evidence, not producer activation or COMMITTED telemetry.

The builder/verifier does not install into another runtime or mutate existing local-data. Original installation, writable private paths, module execution/binding lifecycle, SDK/configuration, main/phase wiring and bounded finish rules require the next exact independent detail/selection. Actual isolated/common activation additionally requires its finite owned acceptance plan. Do not infer these from an archive-only result.
