## First implementation boundary: identity-preserving pure binding

Before packaging, extend the existing pure Diagnostics port only. This additive API is `bind(classes=(), frames=()) -> bool`, accepting finite tuples/lists of `(actual_object, original_descriptor)` pairs. Constructor accepts the same frame-pair form in addition to its existing mapping input. Store frame bindings by id plus strong actual reference and verify `is` during capture; distinct structurally equal original code objects remain separately representable. Preserve exact concrete class matching. Vocabulary is copied at construction; binding cannot add/change phases, error codes, class names or frame descriptors. No I/O, import, compile, reflection loader, emitter lifecycle or registration authority enters the port.

Maximum8192 distinct class identities and32768 distinct frame identities per Diagnostics instance, consistent with the existing manifest class/frame vocabulary limits. Bounds include prior bindings and are checked before retention. One input call has at most8192 class pairs and32768 frame pairs; reject arbitrary iterators/generators before consumption. Exact built-in list/tuple outer containers and exact two-element built-in list/tuple pairs only; descriptors have existing closed shape. Frame source/symbol must be in the copied original vocabulary; class must be an exception class with the original registered name. Reject unknown descriptors, malformed pairs and conflicting remapping of a previously bound actual identity. An identical repeat is an idempotent success; it consumes no additional capacity. Different actual objects with the same registered descriptor are allowed within identity bounds because repeated original module loads create distinct actual objects.

Validate the complete input before mutating either identity map, including cross-input duplicate conflicts. A rejected additive call returns False, increments the existing bounded rejected counter once, retains no invalid payload and leaves both prior maps unchanged. It never raises into business work; constructor invalid trusted configuration still raises the existing configuration error before activation. No exception/traceback/frame objects are retained. Original code/class objects are deliberately strongly held for the bounded instance lifetime. Mapping constructor compatibility remains, but does not establish collision-safe loader input: the future loader uses pairs exclusively.
