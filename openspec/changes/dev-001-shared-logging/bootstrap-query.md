## Assembly

Enable the existing logging bootstrap module as a Java25 application using the existing pinned Micronaut5.2.4 platform, its existing HikariCP7.1.0 managed constraint and PostgreSQL JDBC42.7.14. Add no custom pool, exporter, tracing SDK or new unmanaged library. Compose Clock, ConfiguredLogReaders, EncryptedLogCursors, LogQueries, JdbcLogQueries and existing DeadlineLogRequests/named response executor through Micronaut factories. No business session/tenant fallback. Startup validates private configuration and the log-only read role before accepting normal requests; fixed safe failures reveal neither file contents nor credential/SQL/cause text.

The read datasource uses an explicit logging-only JDBC URL ending exactly /dkp_dev_logs, with no userinfo/query credentials or arbitrary domain DB fallback. Fixed role dkp_log_reader: CONNECT/USAGE and SELECT on dev_logs.events only; no superuser/create-role/create-DB, schema CREATE, event DML or registry reads. Check effective privileges, including inherited role membership and PUBLIC grants, rather than only direct grants or a role-name match. SQL verification belongs in an outbound JdbcReadRoleVerifier, never inline in bootstrap/domain/application. Actual migrations/provisioning run separately as the logging migration owner; the long-running query process receives no owner/writer credentials.

Use the maintained Hikari pool, max32/minIdle0, 1000ms acquisition, 500ms validation, finite positive driver connect/socket limits, a fixed non-sensitive pool name and owned shutdown. Require positive time from the original admitted deadline immediately before and after pool acquisition; expiry after a lease prevents any business work and enters the same cleanup-only path. The fixed1000ms pool timeout never grants a new request budget. Refresh each borrowed connection's remaining network/statement/lock limits from the admitted request as already implemented. The independent five-second response decision and original dependency ownership remain controlling. No unbounded waiter/retry/helper pool. The normal two-second cleanup-only tail is shared by rollback/close; it never creates a business budget or new cleanup thread. Physical OS/driver termination/trickle/endurance proof stays unverified in458459.

## Private config and bind

Dedicated properties dkp.logging.jdbc-url, db-password-file, reader-grants-file and cursor-key-file are required. Each private file is a regular non-symlink owner-only readable file; bounded read (password<=512bytes, key<=65bytes, grants<=1MiB), no raw-value/path exception echo. Password is a generated opaque ASCII secret; cursor key is32random bytes encoded64lowercasehex plus optional newline. Neither is baked into an image/tracked source/browser assets.

The trusted operator-created reader JSON file has exactly schemaVersion:1 and readers (1..4096). Each entry has exactly id, operator, expiresAt, tokenSha256 and optional issuer/tenantId; boolean operator, nonnilUUID, explicit future UTC expiry and SHA256hex of a generated dedicated opaque token. Tenant grants require issuer/tenant; operator grants forbid those claims. Reject duplicate JSON properties before converting to maps/records, wrong types/unknown fields, invalid bounds, duplicate reader IDs/hashes and expired grants. Use the existing pinned Jackson3 strict duplicate-detection and bounded parsing facilities; no handwritten JSON parser. These private configuration files are operator authority, never caller-controlled HTTP authority; the strict untrusted ingestion parser remains a separate required implementation. The service receives only reader-token hashes. The future loopback viewer separately holds its dedicated plaintext read credential server-side. No browser credentials or anonymous common query route.

Default backend bind127.0.0.1; an explicitly configured container-private bind must be published on host loopback by the owned runtime. Do not automatically publish a public HTTP endpoint or weaken normal authentication. Remote CI endpoint/TLS/spool import remains separately selected work. Local viewer stays a separate loopback-only listener per local-viewer.md.
