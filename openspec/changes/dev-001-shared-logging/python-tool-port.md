## API and authority

Add `tools/runtime/tool-diagnostics.py`, a framework-free event constructor. Its `Diagnostics` constructor receives an original SDK Wire codec and its original vocabulary, a nonblocking `emit(event)` callback, explicit correlation UUID, exact class-object→registered-name mapping and exact owned code-object→registered-frame/source mapping. Inject UUID, UTC and monotonic suppliers for deterministic tests. Class/frame mappings are supplied by the trusted original artifact loader, checked against the original vocabulary before activation; arbitrary filename or module-name resemblance is not registration. No Docker, HTTP, filesystem, environment, credential, subprocess, registration or hidden global caller authority belongs in this module.

`operation(phase, *, family='operation', attempt=1, count=0, error_code=None)` returns a context manager. Family is exactly operation, dependency or build, mapped to existing common started/succeeded/failed/cancelled event names. Phase and optional error_code must be in the original vocabulary. Admission emits one STARTED event. Normal exit emits one SUCCEEDED terminal event. Exceptions emit one FAILED terminal event before re-raising the identical exception object; KeyboardInterrupt uses the existing operation.cancelled event and CANCELLED outcome for every family (there is no invented build.cancelled/dependency.cancelled event). SystemExit(None/0) is SUCCEEDED, every other SystemExit is FAILED, and the original exit is always re-raised. Do not catch and reclassify a business exception as a diagnostic validation error. The terminal event uses measured nonnegative bounded integer duration, attempt/count, its own original eventId/time and the explicit correlation. Successful terminal means operation returned, not that cleanup or logging committed: cleanupSettled defaults false.

The yielded scope may update only these typed facts: `status` HTTP100–599, `bytes`, `queueDepth`, `cancelRequested`, `count`, `cleanupSettled`, and `remainingDeadlineMs`, using existing SDK fields and integer/bool bounds. No free-form attributes, error messages, authority/identity override or private resource paths. Invalid caller facts return a rejection result before retention; they do not raise into the original work. Invalid optional scope parameters yield a disabled diagnostic scope with visible rejection counters while preserving the original work/result; invalid trusted construction configuration is rejected before activation. The port checks the final event with the supplied Wire codec before emit. It maintains separately queryable bounded admitted/rejected/emitFailure counters; callback ACCEPTED/DUPLICATE means admission only. Callback failure/rejection, supplier/codec failure or a closed producer never blocks/replaces the original result, repeats a mutation or recursively emits another event. No network/disk flush/worker lifecycle is hidden in this port.

`boundary_start()` returns a nonnegative finite monotonic marker from the injected supplier, or None with a visible diagnostic failure if unavailable. `failure_note(phase, error, *, boundary_started_at, error_code)` records a terminal-only observed failure using exactly existing eventName operation.failed and outcome FAILED, with no family parameter; it never emits STARTED or asserts a matching operation scope. It uses the actual captured exception and nonnegative elapsed time from that previously recorded marker. An absent/nonfinite/future marker rejects the diagnostic note visibly rather than inventing duration0. It shares the same sanitization/nonblocking failure isolation as operation. It returns an admission/rejection result, never raises into the original work and never retains the exception. The phase denotes the measured whole boundary; a registered error code identifies the latest observed inner stage. This is a qualified failure observation, not proof that an inner stage started/finished or a second terminal result of an existing paired scope.

## Safe original exceptions

Capture the actual exception before any safe public mapping. Only an exact registered concrete class object yields exceptionClass; an unregistered subclass is omitted/counted, not replaced by its superclass. Follow an explicit cause, otherwise an unsuppressed context; inspect at most four cause links and32 traceback frames, with visited identities and explicit truncated/unregistered counts. Emit only registered public frame symbol/source/line facts from the trusted exact code mapping. Never retain exception/traceback/frame objects in diagnostic state or emit callback payloads. Omit messages, args, locals, suppressed exception text and unregistered filenames/paths. Exception graph/codec failures degrade diagnostics safely and preserve the original exception.

## First provider-jobs hooks

Add an optional explicit `diagnostics=None` argument to `checkpoint`, `run` and `dm_boundary`. Preserve current callable defaults for existing library tests/callers. `run` passes that same context to all existing checkpoints and the DM boundary. Main remains UNWIRED in this source slice until the original tool artifact/SDK adapter configuration is separately reviewed and installed; no-op tests/defaults are not development adoption.

Register checkpoint phases `PROVIDER_JOBS_` plus the existing AcceptanceStage values: LAUNCH, OPERATOR, DIRECTORY, RUNTIME, CAPACITY, SOURCE_BINDING, PRIVATE_CONTROL, SCANNER, INSPECTOR, DM_BOUNDARY, FINAL_VERIFY, RESULT. Use error code `PROVIDER_JOBS_STAGE_FAILED`. Capture the actual exception through the port inside checkpoint before `AcceptanceFailure(stage) from None`; preserve the original public failure receipt, exception mapping and nested AcceptanceFailure behavior.

The DM boundary's existing phase variable remains authoritative: PREPARED, OLD_BASELINE, BEGIN, VERIFYING, ABORT, CRASH, RECOVERY, OLD_FACTS_AFTER_RECOVERY, SECOND_COMPLETE, OLD_FACTS_AFTER_COMPLETE, FINAL_SNAPSHOT, FINISH, BROWSER_EXIT. Record one boundary_start marker on entry to dm_boundary, before its existing work; do not reset it when phase changes. In its existing exception handler call failure_note with phase `PROVIDER_JOBS_DM_FAILURE`, actual original exception, that original marker, and error code `PROVIDER_JOBS_DM_` plus the latest existing phase value plus `_FAILED`, before retain_dm_diagnostic and rethrow. Its duration measures elapsed whole-DM-boundary work, not the latest inner phase and not capture time. Register this one terminal-note phase and13 closed error codes in addition to the checkpoint phases. No STARTED is invented for the note; paired outer checkpoint remains a distinct phase/scope. The optional hook does not alter the timing/sequence of existing ownership checks, SQL/marker/browser decisions, timeout/restart assertions or finally cleanup. A later source slice adds successful inner-phase scopes and actual SDK delivery before claiming full provider-jobs adoption; do not imply this initial error hook alone completes it.
