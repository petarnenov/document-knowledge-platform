The design table list also includes `membership_history`; its omission from a terse aggregate summary is not permission to drop immutable membership transitions. A policy snapshot payload is server-private and versioned. It contains the COMPLETE ordered membership set, including inactive state and archived collection revision, all affected aggregate/membership/policy revision tuples and document-set revision. Validate payload shape/size on both write/read; unknown persisted schema fails503, never ignored scope. Max50memberships/document gives a bounded exact payload, not caller-supplied pagination. Hash/reference tokens must not encode hidden IDs.

Transaction order: lock/create tenant fence safely, then sorted affected collections, then sorted document scopes, then exact command outcome lock. Resolve same-key race under that order; no scope-dependent lock inversion. Collection creation obtains tenant fence before newrow inserts. Audience changes lock collection before reading its bounded affectedmembership set, then all related document scopes sorted. Initial complete-set evaluation uses coherent bounded MVCC without locks held across HTTP; only the final local phase uses the ordered tenant-fence lock boundary. No network call can cause a lock transfer or a stale committedauthority fallback. ALL initial and final complete DM batch assessments run outside SQL transactions/locks/borrowed connections. Only the live request coordinator admits the final transaction after the final complete batch assessment completes inside contracts/request-budgets.md limits. The final transaction rereads the complete set and current local ACL/noDENY before comparing captured revisions and committing within the SAME final2-second phase (DM<=1.5s + KBlocaltail<=500ms). No remote assessment runs under SQL locks. Pre-admission timeout forbids later transaction admission; already-dispatched COMMIT uncertainty requires durable idempotent reconciliation, not a claim that HTTP cancellation proves rollback.

Current projection CAS uses tenant+ID+expectedRevision. Audit/policy/membershiphistory/command/outbox inserts and every affectedrevisioncounter commit together; invariant violations/revocation/timeouts roll back all. Expectedpolicytoken mismatch is409 only after current actor/resourceauthority; samekey/differentbody same. Tokenhash lookups always scope actor/tenant/document before revealing validity; wrongscope404 and no hiddenpayload.

Migrations must revoke PUBLIC database/schema privileges; migrator owns only KBschema and migrationhistory; runtime has explicit databaseCONNECT/schemaUSAGE and table/sequence privileges only. No runtimeCREATE/ALTER/DROP/TRUNCATE, foreignschema access, schemaownership, superuser/createdb/createrole/inheritedprivilegedrole or grantoption. Immutability requires both SQLprivileges and row/constraint invariants against rebinding current projections. Separate one-shot `kb-migrations` datasource; requestrepositories only `default` DMLcredentials. Do not copy DM credentials or mount DM runtimecatalog into KB as its own authority.

Real PG proof must exercise DMLroles, directforbiddenmutation, duplicate/compositeFK/CAS/overflow, samekey/bodyconflict, rollbackaftereachfactinsert, restartdurability and concurrentaudience/membershipupdates with deterministicbarriers. Keep fsync/synchronous_commit/full_page_writes enabled. Physical restart observes sameownedcontainer/datamounts, actualnewpostmaster and refreshedobservedport if Docker remaps it; neverreplaceprocessrestart with repositoryrecreation. Recovery neverresets revisions/reuses snapshots.

No Kafka delivery or legallyapproved retention duration is established. Preserve immutable evidence on rollback; no automated destructive downgrade. Unknownclassification/retention/workload authority remain failclosed, not empty defaultallow.
