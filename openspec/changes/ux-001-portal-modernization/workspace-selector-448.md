# Inline authenticated workspace selection — #448

Tracking: https://github.com/petarnenov/document-knowledge-platform/issues/448

Status: proposed development clarification; independent review pending. This document grants no architecture, security-control or production-release approval.

## Existing authority and reference

Interactive Design v0.5 demonstrates a native inline workspace selector. The rendered `workspace-switch` references in both themes at 1440/768/390 are the visual authority; the existing shared workspace-field tokens remain unchanged. Prototype workspace names, personas, counts and success notices are synthetic and provide no production authority. The current portal links this field to Workspace access instead of permitting inline selection.

The existing authenticated session query supplies `tenants`, `selectedTenant`, identity and the CSRF token. The existing typed `selectTenant` client posts to `/api/v1/session/tenant` using same-origin credentials, the current CSRF token and an abort signal, and validates the replacement session. No new endpoint, permission inference or backend rule is introduced.

## Interaction and mutation ownership

Replace only the workspace link with a native select containing real session memberships. Its controlled value reflects the authoritative selected tenant; it does not optimistically change while a command is pending. A disabled placeholder represents missing selection or unverified/unavailable session state. Keep the actual-account select disabled, and retain the secondary Workspace access route. Selecting the already selected tenant or a value outside the displayed memberships performs no command. Membership is an input option, never proof of content authorization.

Reuse `useIdentityCommands` for typed tenant mutations and its existing invocation binding, abort, fail-closed authority checks and captured-query cancellation/removal. Preserve the route after selection, consistent with the existing trusted tenant-selection flow; do not reproduce the prototype's synthetic Home reset or success data.

Because shell and Identity can mount the hook simultaneously, identity commands require QueryClient-wide transition arbitration rather than per-hook pending state alone. All hook instances expose shared busy state and synchronously reject a second command while a transition or uncertain-outcome reconciliation is active. `isMutating` alone is insufficient: removing an initiating instance's mutation on unmount cannot release the transition fence. Keep mutation variables opaque invocation IDs and mutation data empty. Do not queue commands or share protected request/session objects in mutation variables. Session expiry remains fail closed through the existing authoritative session query and command error handling; a blocked expiry attempt must be retried after a pending command settles if the context remains invalid. This is frontend command coordination, not a replacement for BFF authorization.

At transition start, cancel captured old-scope protected reads and prevent protected content/actions from yielding usable old-scope results throughout the transition, including already mounted readers and action closures. On tenant success, remove captured obsolete protected queries, recheck originating authority after asynchronous cancellation, then install the validated replacement session including rotated CSRF. Preserve demonstrably fresh scope queries. The displayed tenant remains the last verified tenant during pending state without representing it as usable protected authority.

External session changes or unmount abort and invalidate outstanding work; late command success or failure cannot directly replace the current session. Abort, timeout, a lost response or unavailable/malformed response is not evidence that the server did not commit. Before protected reads or further commands resume after such an outcome, revalidate through the existing typed session query while retaining a shared reconciliation fence across initiating-instance unmount. Failed revalidation remains unavailable/fail closed; a 401 clears authenticated/protected state. A definite denied command retains the verified tenant and exposes bounded accessible error text, never raw response details.

Source limitation: `SessionController.session` reads the session without the synchronization used by `BrowserSessions.select`; therefore a post-abort GET returning the unchanged originating identity/tenant/CSRF snapshot cannot prove the outstanding POST will not subsequently rotate authority. That unchanged snapshot SHALL NOT clear an uncertain-outcome fence. Recovery requires demonstrably fresh server-issued authority, such as a validated rotated session, or explicit sign-in recovery through the existing `/oauth/login/keycloak` entry. Preserve issuer/subject binding throughout reconciliation; neither a locally changed tenant value nor an invented token establishes fresh authority. No timer, retry count, optimistic update or client-side abort is treated as server settlement. This conservative recovery may require signing in again after a lost response; an accessible recovery message and existing sign-in link SHALL explain that limitation. An authoritative externally installed fresh session is preserved; reconciliation must not delete its queries or overwrite it with an older GET response.

Authority pointers (existing code, no backend edits): `services/browser-bff/adapters-in/src/main/java/org/documentknowledge/browserbff/adapters/inbound/SessionController.java`, methods `session` and `select`; adjacent `BrowserSessions.java`, methods `requireSession`, `requireMutation`, `view` and `select`; `apps/admin-portal/src/identity-api.ts`, `parseSession`, `getSession` and `selectTenant`; `apps/admin-portal/src/features/identity/useIdentityCommands.ts`, `current`, `replaceSession` and the opaque invocation guard. The BFF remains responsible for session validity, tenant membership, Origin/CSRF checks and server-issued rotation. This clarification changes no such invariant or contract and does not add immediate global expiry preemption beyond existing behavior.

## Guard dependency direction and implementation scope

The implementation scope includes WorkspaceShell and its tests, identity command/authority feature hooks and tests, a small framework-independent typed request-guard contract, and narrow guard injection at Documents, Uploads, HomeWorkspace and Identity protected query/mutation closures with their focused tests. Existing document-api, upload-api and identity-api clients may receive that guard through their existing request boundary. No current #443 tree, route configuration, server or wire-contract file belongs to this scope.

The feature layer binds a request guard to its QueryClient, exact session scope and transition generation. A guard supplies an abort signal and a synchronous authority assertion; it contains no authorization policy or independent server-state cache. Protected feature callbacks assert before invocation and after awaited completion or failure. The typed clients receive the framework-independent contract by injection, assert before I/O and after asynchronous response/body handling including failure paths, and never import React hooks, QueryClient or feature coordination state. The unguarded session recovery GET remains usable during a fence and is subject to explicit reconciliation freshness checks before committing its result. QueryCache interception, fetch monkeypatching and hidden/disabled UI alone are not substitutes for these guards. Existing BFF checks remain authoritative regardless of frontend fencing.

## Verification and limits

Add causal tests for two simultaneous hook instances, same-turn competing commands, initiating-instance unmount after a potentially committed POST, late completion after attempted second-instance command, and unchanged/failed/fresh revalidation responses. Also cover rotated-session/cache preservation, disabled states, real options, no optimistic selection, denied/error presentation, and absence of inferred account permissions. This implementation window permits focused host tests, typecheck and lint only. They are supplemental.
