## Envelope and accounting

Pinned PipeliningServerHandler starts streaming input with65535bytes of credit and disables autoRead. Each receive cycle may cross the remaining credit by one final buffer. Fixed allocation8192bytes plus maxMessagesPerRead1 bounds that overrun to8192; queued outstanding input is therefore at most65535+8192=73727bytes under the frozen plaintext HTTP/1.1 assumptions. Header/chunk framing consumes raw receive bytes and cannot expand them because request decompression remains disabled. Explicit HTTP decoder max-chunk-size8192 bounds each delivered body piece. This derivation is conditional on verified runtime configuration, not an assertion that arbitrary Netty pipelines follow it.

BaseSharedBuffer.AsFlux subtracts queued bytes and grants receive credit when it emits a piece. PublisherAsBlocking may retain one emitted swap while PublisherAsStream retains its current piece. Account for both independently, up to2*8192=16384bytes, because they are outside the queued-byte tracker. Candidate conservative Micronaut body memory allowance per current request is131072+16384=147456bytes, plus separately accounted framework/request headers, decoder partial input, JDK HTTP egress buffers, Netty allocator overhead and edge buffers. This is not a whole-process memory cap. The tighter derived queue+two-piece occupancy73727+16384=90111 does not replace the configured131072 hard queue allowance.

HTTP/1.1 pipelining can retain data for another request while a prior response is pending. No per-connection total of147456 is claimed for a pipeline of requests. Actual legal coalesced/pipelined tests must establish the pinned handler's read/backpressure behavior, the same per-request queue/bridge envelope, and the explicit count of simultaneously retained request bodies. If the per-request bound cannot be proven, the candidate returns to specification review. No one-unfinished-request restriction or guessed pipeline settlement hook is selected. Aggregate connection/process accounting remains the separate mandatory #222 gate; this narrow amendment does not establish that gate. Existing admission limits govern domain work, not the number of pre-auth network connections. For N independently retained request bodies, the candidate body allowance is N*147456; determining/enforcing an appropriate connection/request concurrency limit and aggregate container headroom remains a deployment/readiness gate, not an invented global DOS guarantee.

## Protocol and TLS scope

The current internal BFF listener is plaintext HTTP/1.1 behind the pinned Nginx TLS1.2/1.3 edge. Freeze explicit HTTP_1_1, disabled direct BFF SSL/QUIC, HTTP decoder8192 and request decompression false. HTTP/2 is not currently selected by Micronaut: HttpServerConfiguration defaults HTTP_1_1 and HttpPipelineBuilder enters h2c/ALPN only for HTTP_2_0. A proposed implementation must verify that the active profile matches this envelope; configuration selecting direct TLS, HTTP2, HTTP3, h2c/ALPN multiplexing or unknown transports fails startup/readiness. An HTTP1 request carrying Upgrade:h2c must not negotiate101 or enter an unaccounted HTTP2 pipeline; no header alone grants a different resource profile. HTTP2 prior knowledge must not execute an HTTP1 protected operation. Public-edge TLS and hostname/CA validation remain mandatory and unchanged; BFF HTTP client destinations/token relay remain fixed. This is not removal of a previously enabled HTTP2 feature.

A future direct-TLS/H2/multiplex deployment needs its own reviewed decryption/frame/connection-and-stream accounting. A raw socket8192 read does not bound TLS-decoded plaintext to8192, and an H2 connection cap is not a per-stream cap. This candidate makes no such claim.

## Failure and lifecycle

Unknown/mismatched allocator size, maxMessages, decoder cap, decompression, autoRead policy, callback order, protocol or tracked queue settings causes finite unavailable readiness or channel close before protected dispatch. No raw pipeline exceptions/headers/body/token are exposed. Normal overflow/cancel/late body paths preserve closed public errors, current authority, no implicit retry, no artifact/receipt success and exact one-shot upstream ownership. A caller timeout is not proof that an upstream write or SQL commit was absent. Existing durable charges/fences/reconciliation remain authoritative. Healthy readiness requires actual new connection policy verification; merely reading configuration or constructing a customizer is insufficient.

## Alternatives

Keep16KiB and shrink/pace the fixture: rejected; valid network bursts and framework initial credit exceed it. Raise to256KiB or100MB because one test passes: rejected; neither proves the receive envelope and100MB would permit artifact-sized buffering. Set allocator8192 alone: rejected; repeated initial-credit reads can still queue65535bytes. Private-field patch/framework fork: not selected. A different public streaming bridge can be reconsidered only with equivalent bounded accounting and independent review.
