# Pinned primary-source basis

These are compatibility/reasoning inputs, not runtime acceptance. Effective dev62a73f0 BFF Gradle locks select Micronaut HTTP5.2.20 and Netty4.2.19.Final; implementation must verify identical pins or return to review. No maintenance/security recommendation or new dependency version is selected.

- [Micronaut5.2.20 PipeliningServerHandler](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http-server-netty/src/main/java/io/micronaut/http/server/netty/handler/PipeliningServerHandler.java): handlerAdded disables autoRead; refreshNeedMore starts another cycle only after readComplete and positive demand; StreamingInboundHandler initial requested65535, decremented for body input and replenished on consumed bytes. Outbound/pipelined behavior requires its own actual tests.
- [Micronaut5.2.20 BaseSharedBuffer](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http/src/main/java/io/micronaut/http/body/stream/BaseSharedBuffer.java): AsFlux.add enforces queued tracker; asFlux.doOnNext subtracts emitted pieces and acknowledges their size upstream. Thus emitted pieces require separate accounting.
- [Micronaut5.2.20 PublisherAsBlocking](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http/src/main/java/io/micronaut/http/body/stream/PublisherAsBlocking.java) and [PublisherAsStream](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http/src/main/java/io/micronaut/http/body/stream/PublisherAsStream.java): one swap plus current stream piece; buffered errors become IOException. InputStream support is not exemption from queued-byte limits.
- [Micronaut5.2.20 NettyServerCustomizer](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http-server-netty/src/main/java/io/micronaut/http/server/netty/NettyServerCustomizer.java): register before server start, CONNECTION specialization and public initial/final pipeline callbacks. Callback timing must be verified, never inferred from an annotation.
- [Micronaut5.2.20 HttpPipelineBuilder](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http-server-netty/src/main/java/io/micronaut/http/server/netty/HttpPipelineBuilder.java) and [HttpServerConfiguration](https://github.com/micronaut-projects/micronaut-core/blob/v5.2.20/http-server/src/main/java/io/micronaut/http/server/HttpServerConfiguration.java): default HTTP_1_1; HTTP2 selection enables separate h2c/ALPN paths. HTTP1 configureForHttp1 installs handlers then customizer callbacks before incoming bytes. No direct-TLS/H2 proof follows from a plaintext receive-size bound.
- [Netty4.2.19.FixedRecvByteBufAllocator](https://github.com/netty/netty/blob/netty-4.2.19.Final/transport/src/main/java/io/netty/channel/FixedRecvByteBufAllocator.java): fixed8192 guess; [DefaultMaxMessagesRecvByteBufAllocator](https://github.com/netty/netty/blob/netty-4.2.19.Final/transport/src/main/java/io/netty/channel/DefaultMaxMessagesRecvByteBufAllocator.java) caps cycle messages and checks autoRead. [DefaultChannelConfig](https://github.com/netty/netty/blob/netty-4.2.19.Final/transport/src/main/java/io/netty/channel/DefaultChannelConfig.java) supports setting allocator; constructor metadata/default mutations mean the final channel must be inspected.
- [Netty4.2.19 AbstractNioByteChannel](https://github.com/netty/netty/blob/netty-4.2.19.Final/transport/src/main/java/io/netty/channel/nio/AbstractNioByteChannel.java): allocate/read/fireChannelRead then continueReading, followed by readComplete. Actual enabled Linux/Mac channel families must prove equivalent bounds; a NIO source review does not certify native epoll/kqueue automatically.
- [Official Micronaut advanced body documentation](https://docs.micronaut.io/5.0.x/http/#advancedBodyAccess): InputStream consumption must be off event loop, byte-body ownership/backpressure and split-consumer accounting. Existing ExecuteOn(BLOCKING) remains required; slow-consumer tests must observe real network backpressure.

Public source files must be inspected at these pins; no private framework reflection, shadow class or fork is permitted. Protocol/runtimes outside this proof remain an explicit unavailable readiness condition, not an inferred equivalent configuration.
